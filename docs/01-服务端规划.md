# 在线VWI发布项目 · 服务端规划

> 版本 v0.2（规划稿）　状态：待确认后进入实现
> v0.2 变更：**移除权限管理**（用户决定"先不考虑"），服务端不鉴权，仅限内网部署。
> 本文件只规划**服务端**。管理端、安卓端的边界在文末「上下游约定」中标明。

---

## 0. 一句话定位

服务端只做三件事：**存内容、管版本、发出去**。
不做播放、不做转码、不做排产。凡是不属于这三件事的需求，先问「能不能放到别处」。

> **前置条件**：本期无鉴权、无角色。服务端只能跑在**车间内网**，且不得做端口映射到公网。
> 这不是"以后再说"的待办，而是一条硬性部署约束 —— 没有登录的发布系统暴露在公网，
> 等于把整条产线的看板交给路过的人。

## 2. 逐板块规划

### 2.1 鉴权：本期不做，但留接入点

**本期做法**

- 管理端接口**不做登录**，任何人打开地址即可编辑与发布。
- 终端令牌（2.2）**保留** —— 它不是权限管理，而是"让终端能认路"，且成本极低。
- 不做角色、不做会话、不做登录失败限速，`user` / `session` 两张表**本期不建**。

**为什么保留终端令牌**：没有它，任何一台能连内网的设备都可以把自己伪装成某个工位，
把内容错发到别处。这是**定位问题**，不是权限问题。

**二期的加回方式（不改业务代码）**

所有写接口集中挂在一个 `guarded()` 包装器上，二期只需把它从"直通"换成"校验会话"：

```js
// 本期
const guarded = (handler) => handler;
// 二期
const guarded = (handler) => (req, ctx) => {
  const user = userByToken(cookie(req).vwi);
  if (!user) return sendError(res, 401, '请先登录');
  ctx.user = user;
  return handler(req, ctx);
};
```

**代价（必须知情）**

| 失去的能力 | 实际风险 |
|---|---|
| 谁改的、谁发的不可追溯 | 出问题时无法定位责任人 |
| 任何人都能回滚或发布 | 误操作影响整条线 |
| 无法限制只读账号 | 外人也能改内容 |
| 无法审计 | 合规场景过不了 |

如果只是"一期先跑起来"，这些都可以接受；**如果这套系统要交付给客户或过审计，二期必须补**。


### 2.2 终端令牌

- **一机一令牌**，`station_token` 表存储，可随时吊销。
- 终端鉴权走 `?code=<工位编码>&token=<令牌>` 或请求头，**不给终端开账号**。
- 令牌格式：32 字节随机、base64url，不含语义。
- 配对流程（三选一，建议 A）：
  - A. 管理端点击「生成配对码」→ 显示二维码 → 终端扫码写入配置
  - B. 管理端生成 6 位配对码 → 终端手工输入
  - C. 批量预置配置文件（适合一次性部署 50 台）
- 令牌**不设自动过期**（产线机器不该半夜失效），靠人工吊销。
- 吊销即断开该终端所有 SSE 连接，并拒绝后续拉取。

### 2.3 内容树

```
Line 产线
 └ Board 看板            ← 多个工位可共用同一看板（线首屏、总览屏）
    └ Page 页（有序）     ← 一屏 = 一页
       └ Block 块         ← 内容的最小单位，按 slot 落位
Station 工位  ──引用──>  Board
```

**为什么 Board 独立一层**：避免「改一次内容要改 10 个工位」。工位只负责「我在哪、我显示哪块看板」。

**块类型（10 种）**

| type | 用途 | 关键字段 |
|---|---|---|
| `heading` | 页标题 | text |
| `text` | 正文说明 | text |
| `param` | 关键参数 | label, value |
| `warn` | 警示 | level(L1/L2/L3), text |
| `image` | 图片 | mediaId, fit(contain/cover), caption |
| `video` | 视频 | mediaId, loop, mute, startSec |
| `list` | 编号清单 | items[] |
| `clock` | 时钟 | format |
| `qr` | 二维码 | value |
| `spacer` | 占位 | — |

**布局（5 种）与槽位契约**

| layout | 槽位 | 适用 |
|---|---|---|
| `stack` | head / main / side | 通用单列 |
| `step-focus` | head / main / side | **VWI 主力**：主视图 + 右侧参数与警示 |
| `split` | head / left / right | 图左文右对照 |
| `video-focus` | head / stage / foot | 全屏视频 + 底部说明 |
| `grid` | head / c1 / c2 / c3 / c4 | 多图并列 |

服务端只校验「这个 layout 允许哪些 slot」，具体像素排布由渲染端决定，**服务端不生成任何图片**。
这样加版式不用改服务端，也不用重发安卓 APK。

**草稿态与生效态**

- `page` / `board` 表里的内容是**草稿**，改了就改，不影响现场。
- 现场看到的永远是某个 `release` 的快照。
- 管理端需要显示「草稿有未发布的改动」——用 `board.updated_at > release.created_at` 判断。

### 2.4 发布与版本

**发布单不可变**：生成后 `manifest` 落库，永不修改。要改就发新单。

**manifest 结构（按工位裁剪后下发）**

```json
{
  "releaseId": "rel_xxx",
  "seq": 12,
  "digest": "sha256:...",
  "station": { "code": "L01-OP30", "name": "OP30 电机装配" },
  "board": { "id": "bd_xxx", "name": "OP30 电机装配" },
  "pages": [
    {
      "id": "pg_xxx", "ord": 0, "layout": "step-focus",
      "title": "第 1 步 · 装配前检查", "duration": 20,
      "blocks": [
        { "id": "bk_1", "type": "heading", "slot": "head", "text": "装配前检查" },
        { "id": "bk_2", "type": "video", "slot": "main", "mediaId": "a1b2c3d4", "loop": true }
      ]
    }
  ],
  "media": {
    "a1b2c3d4": { "sha256": "...", "size": 8123456, "mime": "video/mp4", "url": "/m/a1b2c3d4?e=...&s=..." }
  }
}
```

**发布前预检（7 项，任一不过即拒绝）**

1. 页面数 ≥ 1，每页至少 1 个可见块
2. 所有 `mediaId` 在 `media` 表存在且文件在磁盘上
3. 每页 `duration` 在 3–600 秒
4. L1 警示块必须有文字（不许空警示）
5. 图片/视频块必须有 `mediaId`
6. 页面标题非空
7. 整线涉及的所有工位都绑定了看板

**seq 并发安全**：`seq = MAX(seq)+1` 在同一事务内取，`UNIQUE(line_id, seq)` 兜底。冲突就重试一次。

**三个动作的语义**

| 动作 | 实现 | 影响范围 |
|---|---|---|
| 发布 | 新建 release，产线 `active_release_id` 指向它 | 整线所有工位 |
| 灰度 | 只改 `station.override_release_id` | 指定工位 |
| 回滚 | 把 `active_release_id` 指回旧 release，**不新建** | 整线 |
| 吊销 | `release.revoked_at` 置位，终端拒绝使用 | 全部引用处 |

**终端取内容的判定**

```
终端带 seq + digest 请求
  → 命中当前发布且 digest 一致 → 304，返回 { unchanged: true }
  → 不一致 → 200 + manifest
```

### 2.5 媒体仓库

- **内容寻址**：`data/media/<sha256前2位>/<sha256>.<ext>`，同文件只存一份。
- 上传即算 sha256，命中已有记录直接返回（秒传）。
- 单文件上限 512MB，类型白名单（图片/视频/音频/PDF）。
- **访问签名**：`/m/<id>?e=<过期毫秒>&s=<HMAC-SHA256 前 22 位>`，默认 24 小时。
- **必须支持 Range**：视频拖动、断点续传、安卓端分片下载都依赖它。
- 清理：只删「没有任何 page 引用」的媒体，且必须显式触发，不做自动删除。
- 不做转码。工程部上传前自己转成 1080p H.264，服务端只负责存和发。

### 2.6 工单

**状态机**

```
open ──开工──> running ──关单──> closed
  └──取消──> cancelled
```

**核心规则**

- 开工瞬间，把 `release_id` 写进工单并锁定。
- 在制期间产线发新版：工单不动，终端界面上只挂「有新版本」角标。
- 关单后记录 `done_qty`，后续统计按工单维度可追溯。
- 报工必须幂等：终端带 `client_id`（一次报工的 UUID），重复提交不重复累加。

**明确不做**：MRP、排产、BOM 展开、物料齐套、SN 级追溯、设备管理。

### 2.7 日志与统计

**两张表，不按天分表**

| 表 | 内容 | 索引 |
|---|---|---|
| `play_log` | 工位、页、开始/结束、停留毫秒、是否看完、发布单、工单号 | `(started_at)`、`(station_id, started_at)` |
| `event_log` | 上线/掉线/同步/指令/错误/操作 | `(at)` |

**写入策略**：内存攒批，200ms 或 50 条刷一次；进程退出前强刷。**绝不同步写盘阻塞播放请求**。

**统计口径（固定下来，避免各人算法不同）**

- 页覆盖率 = 有播放记录的页 ÷ 该看板应播页数
- 终端在线率 = 90 秒内有心跳的工时数 ÷ 总工位数（按小时聚合）
- 版本分布 = 按 `last_seq` 分组统计工位数

**保留策略**：在线 90 天，之后导出归档文件并从表中删除（按月一个文件）。

### 2.8 报表导出

- **流式生成 CSV 和 XLSX，不落盘、不排队、不轮询。** 50 工位的量级用不上异步任务。
- 四个固定报表：播放明细、页覆盖率、终端在线率、版本分布。
- 单次导出上限 90 天，超出要求用户分批。
- 中文文件名用 RFC 5987 双写（`filename=` ASCII + `filename*=` 百分号编码），否则浏览器报头异常。

### 2.9 运维与安全

| 项 | 做法 |
|---|---|
| 健康检查 | `GET /api/health` 返回 db 可写、磁盘剩余、媒体数、终端在线数 |
| 磁盘水位 | 剩余 < 2GB 时在管理端顶部告警；< 500MB 拒绝上传 |
| 备份 | `data/vwi.db` + `data/media/` 一起打包，缺一不可 |
| 恢复演练 | 备份脚本必须带自检（校验 db 可打开、媒体数与记录一致） |
| 日志轮转 | 进程日志按 10MB 滚动，保留 7 个 |
| 审计 | 本期只记「发生了什么」（发布/回滚/删除），不记「谁做的」，二期补操作人 |

**块的存储决定**：`page.blocks` 存 JSON 一列，不拆表。
理由：块永远整页一起读、一起写，拆表会导致每页 N 次查询，是过度设计。

## 5. 七条工程约束

1. **无鉴权只允许内网** —— 不做端口映射、不放公网，这是部署红线而非待办
2. **写操作幂等** —— 终端断网重试，报工不能重复累加（靠 `client_id` 唯一约束）
3. **时间一律服务端时间** —— 安卓盒子时钟常年不准
4. **大文件不进内存** —— 上传、下载全程流式
5. **发布单不可变** —— 改就是新发一版，历史永远可查
6. **终端看到的一切带版本号** —— 否则无法判断谁在旧版
7. **推送只加速，真相靠拉取** —— SSE 只发「有新版本」，终端自己来取

## 6. 实现顺序

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P0** | 内容树 + 媒体 + 发布 + 终端拉取 | 一台安卓机能拉到内容并循环播放；改一页重发后 30 秒内生效 |
| **P1** | 工单 + 指令 + 日志统计 + 导出 + 灰度回滚 | 工单开工锁版；拔网线继续播；回滚 10 秒生效；报表能导出 |
| **P2** | SSE + 备份自动化 + 许可证 + **权限（如需要交付客户）** | 发布后 2 秒内终端收到通知 |

## 7. 上下游约定

服务端对两端的承诺，越界就是设计错误：

**对管理端**
- 内容的唯一真相在服务端，管理端不本地缓存草稿（关掉浏览器不丢）
- 每页保存是「整批覆盖」，不是增量 patch，避免排序错乱

**对安卓端**
- 只提供三样东西：manifest、媒体地址、指令队列
- 不要求终端理解业务，终端只按 `layout` + `slot` 渲染
- 断网时终端用本地缓存继续播，服务端不承担「断网容错」的责任
