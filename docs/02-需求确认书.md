## 1. 要解决的问题

车间工位需要按**产品型号 + 工序**显示对应的作业指导书（图片）和操作视频。
换型时，整条线的每个工位要同时换成新型号的内容——**现在靠人工换纸、换 U 盘、或者根本没人换**。

一期目标不是"做一套信息发布系统"，而是：

> **班长在服务器上点一下换型号，5 个工位在 10 秒内全部变成新型号的作业指导书。**

---

## 2. 范围

| 项 | 一期范围 |
|---|---|
| 产线 | 1 条 |
| 工序 | **5 道（一道工序一台屏，共 5 台屏）** |
| 工位 | **不设工位实体**，屏的身份就是它所在的工序 |
| 内容类型 | **图片**（作业指导书）+ **视频**（关键动作），循环播放 |
| 换型方式 | 服务端远程切换（手动选型号） |
| 网络 | 无线（5GHz WiFi） |
| **屏幕** | **19 寸，1280×1024（5:4）** |
| **接收端** | **Windows 迷你主机 + Electron exe** |

---

## 3. 角色与场景

| 谁 | 在哪 | 做什么 |
|---|---|---|
| 工程部 | 办公室 | 上传某型号某工序的图片和视频，设定播放顺序 |
| 班长 | 办公室或产线 | 换型时在服务器上选新型号，一键下发 |
| 操作工 | 屏前 | 只看，不操作。屏幕自动循环播放当前内容 |
| 维护 | 随时 | 终端断电重启后能自己回到当前型号继续播 |

**操作工不需要任何操作**——这是硬要求。屏边不放键盘鼠标，不要求点"下一步"。

> **没有工位这一层之后，换型是全网统一的**：不存在"这台先换、那台后换"，也不存在某台屏单独设型号。一次换型 = 5 台屏同时变。这正是车间的真实情况（一条线同时只做一个型号），也让实现和验证都简单了一个量级。

## 4. 内容模型

```
产品型号 Model（如 X200、X300）
  └─ 工序 Process（OP10 / OP20 / OP30 / OP40 / OP50）
       └─ 播放清单 Playlist
            ├─ 图片 ×N（作业指导书，每张停留 N 秒）
            └─ 视频 ×N（播完即下一项）
            整轮循环
```

**规则一：一台屏就是一道工序，换型只换型号。**
屏上没有"工位"这个概念。OP30 那台屏永远显示 OP30 的内容，它的工序不随换型变化；换型时变的是"这道工序现在做哪个型号"。
所以屏的身份 = 工序代码（`OP30`），配置里只填这一个值，不注册、不建档案。

**规则二：同一型号下，每个工序的内容各不相同。**
X200 的 OP10 和 OP30 是两套完全不同的图和视频。内容不是"按型号一套"，而是"按（型号 × 工序）一套"。

以 5 道工序、10 个型号计算，内容总共有 **10 × 5 = 50 套**。

| 型号 \ 工序 | OP10 | OP20 | OP30 | OP40 | OP50 |
|---|---|---|---|---|---|
| X200 | 清单 | 清单 | 清单 | 清单 | 清单 |
| X300 | 清单 | 清单 | 清单 | 清单 | 清单 |
| … | | | | | |

## 5. 换型与遥控切换机制（决定验收能否通过）

### 5.1 切换是"整批原子切换"，不是一台一台换

一次换型 = 服务器发一个型号号 → **5 台屏在同一瞬间整体翻到新型号**。

```
班长点"切换到 X300"
        │
        ▼
  服务器：current_model = X300，seq +1，唤醒所有挂起的终端
        │
   ┌────┴────┬────────┬────────┬────────┐
   ▼         ▼        ▼        ▼        ▼
 OP10屏    OP20屏   OP30屏   OP40屏   OP50屏     ← 同一瞬间，全部翻
 X300      X300     X300     X300     X300
```

**必须一起切的三条理由**（都是车间的真实后果，不是技术洁癖）：

| 不同时切会怎样 | 后果 |
|---|---|
| 逐台下发 | 一小时内 5 台屏新旧混杂，前道按新型号做、后道还按旧型号做，**直接产生批量错件** |
| 逐个工序滚动切 | 中间几十秒里 OP10 已是新型号、OP20 还是旧型号，同样是混批 |
| 边下边播 | 屏上第 1 张是新图、第 5 张还是旧图，工人无法判断自己看的是哪一批 |

所以规则定死：**要么整批全翻，要么一台都不翻。**没有中间状态。

### 5.2 但要"翻得动"，本地得提前备着

原子切换的前提是新型号的内容**已经在本地**。两条纪律配合：

| 步骤 | 发生什么 |
|---|---|
| 平时 | 终端在空闲时把**下一个可能用到的型号**（服务器指定或按最近使用排序）下载到"预备槽" |
| 换型 | 服务器只广播一个型号号，5 台屏**同时**收到 |
| 终端 | 预备槽已命中 → **0 秒翻**；未命中 → 现场下载该型号本工序内容（约 27MB），**备齐后才翻** |
| 翻完 | 旧的当前槽清空删除，预备槽升为当前槽，再预取下一个 |

**"备齐后才翻"这条不能松**：宁可让班长多等 5 秒，也不能让工人看到半新半旧的画面。
切换未命中时终端顶栏显示 `准备中 3/11`，翻完才换画面——这 5 秒是可控的，混批是不可控的。

### 5.3 旧文件客户端自己删，不保留

| 项 | 规则 |
|---|---|
| 什么时候删 | 新型号**切换成功、画面已翻过去之后**立即删，不等定时任务 |
| 删什么 | 上一型号在**本工序**下的全部本地文件（图 + 视频） |
| 本地常驻 | **最多 2 套**：当前播放的 1 套 + 预备的 1 套（≈ 27MB × 2 ≈ **54MB**） |
| 不保留 | 不归档历史型号、不做"回滚到上一型号"的本地快照、不留任何旧版本副本 |
| 服务端配合 | 服务端的媒体文件是**内容寻址、多型号共用**的，只在无人引用时才清理（`/api/media/gc`），与终端删除互不影响 |

**为什么本地只留 2 套是划算的**：单台终端只播自己那道工序，一套内容 ≈ 27MB，
2 套才 54MB——但换来的是"切换 0 秒"。刻意不缓存全部 10 个型号，是因为**旧内容留在屏上没有任何价值，
只有占地方和"播错了型号还留着"的风险**。

> 若日后出现"切换未命中太频繁"（比如一天 3 次换型、型号切换顺序无规律），
> 只需把预备槽从 1 个扩到 3 个，磁盘代价 81MB，代码改动集中在预取策略一处，不动切换通道。

### 5.4 内容不全时怎么办（工程部没做完）

车间不能因为工程部漏了一张图就停产，所以**允许切换**，但必须让人看见：

- 新型号本工序内容**缺项** → 照切，缺的那几项跳过不播
- 顶栏常驻橙色标记 `内容不全 8/11`
- 管理端型号列表里该型号标红

**不允许**的是"静默降级"——屏上看着正常、实际少了两张关键图，比直接报错危险得多。

### 5.5 终端上的可见状态

屏幕顶栏一行字：`X300 / OP30`，右下角小字 `第 2 张 / 共 7 张`。
工人一眼能确认"我播的是不是这批货"——在 19 寸屏上，这行字必须够大（≥28px），不能做成装饰性小字。

异常状态也用顶栏表达，且**必须让 1 米外站着的人看见**：

| 状态 | 顶栏显示 |
|---|---|
| 正常 | `X300 / OP30`　（白字） |
| 离线 | `X300 / OP30 · 离线`　（灰底小标记，不打扰） |
| 内容不全 | `X300 / OP30 · 内容不全 8/11`　（**橙色**） |
| 切换准备中 | `正在切换到 X400 · 3/11`　（**蓝色**，此时画面仍是旧内容） |

## 6. 屏幕基线（D5 = 19 寸，本次修订的核心）

### 6.1 先说一个必须先解决的冲突

原方案按 42–55 寸、观看 3 米写的。**19 寸放在 3 米外，图上细节是看不清的**，这不是调字号能救回来的：

| 距离 | 19 寸屏的视角宽度 | 相当于 | 判断 |
|---|---|---|---|
| 1.0 m | 21.3° | 42 寸屏在 2.2 m | 舒适，接近 1:1 像素 |
| 1.2 m | 17.9° | 42 寸屏在 2.6 m | **推荐** |
| 1.5 m | 14.3° | 42 寸屏在 3.3 m | 可接受下限 |
| 3.0 m | 7.2° | 42 寸屏在 6.6 m | **不可用**：单像素视角 0.34′，低于人眼 1′ 分辨力，等于分辨率被"抹掉"一半 |

19 寸 5:4 面板可视区 **376.9 × 301.5 mm**，1280×1024 时像素间距 **0.294 mm**。
按 1′ 视觉分辨力反算：**距离超过 1.5 米，1 像素就看不见了**——指导书上的螺丝孔位、线束走向这类细节正好是 1–3 个像素宽。

**结论（R1 已核实）：显示器放在工作台上，观看距离 1.0 米 —— 19 寸成立，且余量充足。**

1.0 米处视角 **21.3°**，相当于 42 寸屏在 2.2 米，是这类看板最舒服的区间；单像素视角 **1.01′**，正好落在人眼分辨力上，
意味着**屏上 1 个像素对应眼睛能分辨的 1 个点，分辨率没有浪费也没有不足**——1280×1024 就是这台机器的正确分辨率，不需要 1080p，也不该降到 1024×768。

原来担心的"3 米看不清"不成立，A7 可以按 1.0 米验收。
但仍有一条边界要守住：**工作台距离改成 1.5 米以上（例如操作工要退后取料）时，细节就开始糊**，屏必须留在伸手可及的范围内。

### 6.2 版式（5:4 单列，不做左右分栏）

5:4 接近方形，左右分栏会让两边都变窄（各 620px），字和图都挤。定为**单列纵向**：

```
┌──────────────────────────────┐ 1280
│ 顶栏 88px  X300 / OP30   时间 │
├──────────────────────────────┤
│                              │
│        主区（图片/视频）        │ 约 780px
│                              │
├──────────────────────────────┤
│ 底栏 120px  第 2/7 张 · 进度点 │
└──────────────────────────────┘ 1024
```

- 图片**满宽显示**（1280×1024 或 4:3 构图的图，几乎占满屏）
- 视频 16:9 时 → **上下留边，不裁切**（1280×720，上下各 152px，用深灰 #1a1a1a 填，不用纯黑）
- 一条视频独占一屏，不在同一屏里塞图和视频

### 6.3 字号（按 1.2 米观看反算，不是拍脑袋）

按"舒适阅读 = 2 倍最小可辨高度"：

| 用途 | 最小字号 | **实际取值** | 说明 |
|---|---|---|---|
| 顶栏型号/工序 | 14px | **32px** | 抬眼看一眼就能确认 |
| 图片内文字 | — | 图内字号由工程部出图控制，**出图时按 1.2 米验看** | 见 6.4 |
| 底栏页码 | 14px | **28px** | |
| 警示/红线提示 | 18px | **36px + 色块 + 图标** | 不靠颜色单独表达（色弱） |

对比度 ≥4.5:1，禁用纯红大面积底色（久看刺眼、长时间静态会残影）。

### 6.4 图片与视频规格（工程部按此出，否则屏上必糊）

| 项 | 规格 | 为什么 |
|---|---|---|
| 图片尺寸 | **1280×1024（5:4）或 1024×768（4:3）** | 16:9 截图投到 5:4 屏上，上下各浪费 152px，实得只有 25% 面积 |
| 图片格式 | JPEG，质量 85，**单张 ≤400KB** | 50 套 × 10 张 = 500 张，按 400KB 共 200MB，可接受 |
| 图片内字号 | 图上标注文字**高度 ≥24px**（按 1280 宽出图） | 缩放到屏上后仍 ≥1′ 视角 |
| 视频分辨率 | **1280×720**，H.264，≤3 Mbps | 屏只有 1024 高，1080p 是纯浪费；720p 在 19 寸上肉眼无差 |
| 视频时长 | **单段 ≤60 秒** | 长了工人等不到下一步，且缓存占空间 |
| 视频大小 | **单段 ≤25MB** | |
| 禁止 | 手机竖拍、带水印、屏幕录制带鼠标 | 竖拍在 5:4 屏上只剩中间一条 |

### 6.5 硬件（D1 = exe + Windows 迷你主机，已定）

| 项 | 要求 | 说明 |
|---|---|---|
| CPU | Intel N100 / N150（4 核，TDP 6W） | 硬解 720p/1080p 无压力 |
| 内存 | **8GB 起，建议 16GB** | N100 单通道单插槽，后期加不了 |
| 存储 | **256GB NVMe SSD 起** | 终端常驻仅约 54MB，128GB 也够，但 256GB 不贵，留出系统更新余量 |
| 无线 | **必须 WiFi 6（AX201/AX210）** | 最容易踩坑的一条，见下 |
| 视频输出 | HDMI 2.0 | 接 19 寸显示器 |
| 系统 | Windows 11 专业版 | 需能关闭自动更新 |
| 功耗 | 10–15W | 全年电费约 60 元 |

| 型号 | 配置 | 参考价 | 备注 |
|---|---|---|---|
| **铭凡 UN100D**（推荐） | N100 / 16GB / 512GB / Win11 | ≈ ¥1519 | 双 2.5G 网口，开箱即用。**默认网卡 Intel AC 9560 = WiFi 5，需换 AX210** |
| 铭凡 UN100D 低配 | N100 / 8GB / 256GB | ≈ ¥1199 | 同样需换网卡 |
| 零刻 EQ12 | N100 准系统 | ≈ ¥800 | 自配 8GB + 256GB（约 +¥250） |
| 极摩客 G3 | N150 准系统 | ≈ ¥699 | 金属机身，散热好，同样自配 |

**19 寸显示器要盯的三件事**（比主机更容易忽略）：

1. **分辨率必须是 1280×1024**。少数 19 寸标 1366×768，那是 16:9 面板，版式要重做，采购前看清楚。
2. **接口要是 HDMI 或 DP**。老工业屏只有 VGA 时，加一个 HDMI→VGA 转接（约 ¥30），并把分辨率锁在 1280×1024@60。
3. **面板优先 IPS**。19 寸工业屏大量是 TN，工人站着从上方看会整片发灰、颜色反转——这一点在样机上必须亲眼验证。

其余：亮度 ≥250 cd/m²（车间照明强选 350）、雾面不反光、VESA 75/100 孔位、宽温 0–50℃。

**"放在工作台上"带来的三条额外要求**（1 米距离才有的问题，3 米时不存在）：

| 项 | 要求 | 不做的后果 |
|---|---|---|
| **仰角** | 屏面**上仰 10–15°**，屏幕中心略低于人眼（约 1.25–1.35m 高） | 屏平放台面上时，站着看是斜视 40°+，TN 面板会整片发黑，IPS 也会掉对比度 |
| **防眩光** | 必须**雾面**，且避开顶灯正下方（或加遮光罩） | 1 米距离时顶灯在屏上形成的高光斑正好盖住图面中间，看图全废 |
| **防护面** | 加 **3mm 亚克力或钢化玻璃面板**，边框密封 | 工作台上工人拿零件、工具、扳手，磕碰和油污落在屏上是必然事件 |

另外，1 米距离意味着**屏就在手边**——必须确认这台机器不带触摸功能，避免工人误触（一期不做触摸交互，见第 8 节）。

### 6.6 无线网络部署参数

| 项 | 要求 | 原因 |
|---|---|---|
| 频段 | **只走 5GHz** | 车间变频器、伺服、对讲机、无线扫码枪全在 2.4GHz |
| 协议 | 802.11ac 起，推荐 802.11ax | |
| 信道 | 149/153/157/161，带宽 40MHz | 5 台用不到 80MHz，40MHz 更抗干扰 |
| 单台实测 | **在屏所在位置**测到 ≥50Mbps 下行 | 不是站在路由器旁边测 |
| AP 数量 | 5 台屏集中 → 1 台；跨度 >30m 或有承重墙 → 2 台 | |
| 服务器 | 走**有线**接 AP | 唯一数据源不能无线 |
| SSID | 单独一个，不与办公网共用；能关 2.4G 就关 | 防止终端漂到 2.4G |

### 6.7 体积与带宽（按 19 寸规格 + "本地只留 2 套"重算）

| 项 | 计算 | 结论 |
|---|---|---|
| 单套内容（一个型号 × 一道工序） | 10 图 × 0.4MB + 1 视频 22.5MB（720p/3Mbps/60s） | **约 27MB** |
| **服务器总库** | 50 套 × 27MB | **约 1.4GB**（只存在服务器上） |
| **单台终端常驻** | 当前 1 套 + 预备 1 套 | **约 54MB** |
| 一台终端首次装机 | 54MB，按实测 50Mbps 下行 | **约 10 秒** |
| 换型（预备已命中） | 只发一个型号号 | **<1 秒** |
| 换型（预备未命中） | 现场下载本工序一套 27MB | **约 5 秒**，仍满足 A1 的 10 秒 |
| 反向收益 | 终端磁盘占用从"全量 1.4GB"降到 54MB | **26 倍**，且旧内容不留 |

> 这是"旧文件不保留"带来的额外好处：终端不再需要为大缓存留空间，
> 256GB 盘在 5 台机器上全无压力，日后型号增到 50 个也不会撑爆终端。
> 服务器端 1.4GB 是**内容寻址、型号间去重**后的量级——同一张标准图被 6 个型号引用时只存一份，实际通常小于这个数。

## 7. 验收标准

| # | 标准 | 怎么测 |
|---|---|---|
| **A1** | **服务端切换型号，5 台屏 10 秒内全部变成新内容，且最先变与最后变的间隔 ≤1 秒** | 5 台屏摆一排用一台手机同时录，回放看时间戳。前半句测"切得动"，后半句测"切得齐" |
| A2 | 切换过程不黑屏、不闪白、不回到桌面 | 录像回看 |
| A3 | 拔掉 AP，终端继续正常播放，且仍能响应切换（切到已备好的型号） | 断网 30 分钟后测切换 |
| A4 | 断网 8 小时，播放不中断、不卡顿 | 夜间断网，第二天看 |
| A5 | 单台断电重启，自动回到当前型号继续播，不需人操作 | 直接拔电源 |
| A6 | 整线换型（含新内容下载）5 分钟内完成 | 掐表 |
| **A7** | **在 1.0 米处（工作台实际观看距离），能看清指导书图上 2mm 的特征** | 拿游标卡尺量一个实物特征，站屏前看，与实物比对 |
| **A8** | **切换成功后，上一型号的本地文件确实被删除** | 切换后进终端目录看：只剩当前 1 套 + 预备 1 套，旧型号文件数为 0；连续切 3 次，目录大小不增长 |
| **A9** | **不存在半新半旧的画面** | 在"未预备"的情况下切换（把预备槽清空再切），观察画面：要么整屏旧内容 + 顶栏"准备中"，要么整屏新内容，**不允许一屏里混两个型号** |

**A1 和 A7 过了，这套系统就算立住了。** A8 / A9 是"一起切、不留旧"这两条纪律的可验证形式，缺了就等于没做。

> A7 的判据必须是"能不能看清 2mm 特征"，而不是"字大不大"——指导书的价值在细节，字大而细节糊等于没用。

## 8. 明确不做（一期）

- ❌ 工单 / MES / ERP 对接（本期型号手动选）
- ❌ 扫码换型（预留接口，不做界面）
- ❌ 多区域分屏、跑马灯、时钟、网页、二维码
- ❌ 播放日志统计与报表导出（仅保留最小运行日志供排障）
- ❌ 用户登录、角色权限（**服务端只能部署在车间内网**）
- ❌ 4K、视频转码（工程部按 6.4 的规格产出）
- ❌ 远程截屏、远程重启
- ❌ 手机端、外网访问
- ❌ 触摸交互（19 寸是只读看板，不装触摸）
- ❌ **工位 / 终端注册管理**（没有工位实体：一台屏 = 一道工序，屏上只配一个工序代码）
- ❌ **分屏独立设型号**（换型全网统一，不支持某台屏单独跑别的型号）
- ❌ **本地历史型号归档**（旧文件切完即删，不做"回滚到上一型号"的本地快照）
- ❌ **边下边播 / 分批生效**（必须备齐后整批翻，宁等不做半新半旧）
