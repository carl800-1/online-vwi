## 1. 要解决的问题

车间工位需要按**产品型号 + 工序**显示对应的作业指导书（图片）和操作视频。
换型时，整条线每道工序的屏要同时换成新型号的内容——**现在靠人工换纸、换 U 盘、或者根本没人换**。

一期目标不是"做一套信息发布系统"，而是：

> **班长在服务器上点一下换型号，5 道工序的屏在几秒内、同一瞬间一起变成新型号的作业指导书。**
> （正常网络 3–6 秒；验收红线是 5 分钟内完成，见 5.3 与 A1）

## 2. 范围

| 项 | 一期范围 |
|---|---|
| 产线 | 1 条 |
| 工序 | **5 道（一道工序一台屏，共 5 台屏）** |
| 工位 | **不设工位实体**，屏的身份就是它所在的工序 |
| 内容类型 | **图片**（作业指导书）+ **视频**（关键动作），循环播放 |
| 换型方式 | 服务端远程切换（手动选型号） |
| 网络 | 无线（5GHz WiFi） |
| **屏幕** | **19 寸，1280×1024（5:4）** |
| **接收端** | **Windows 迷你主机 + Electron exe** |

## 3. 角色与场景

| 谁 | 在哪 | 做什么 |
|---|---|---|
| 工程部 | 办公室 | 上传某型号某工序的图片和视频，设定播放顺序 |
| 班长 | 办公室或产线 | 换型时在服务器上选新型号，一键下发 |
| 操作工 | 屏前 | 只看，不操作。屏幕自动循环播放当前内容 |
| 维护 | 随时 | 终端断电重启后能自己回到当前型号继续播 |

**操作工不需要任何操作**——这是硬要求。屏边不放键盘鼠标，不要求点"下一步"。

> **没有工位这一层之后，换型是全网统一的**：不存在"这台先换、那台后换"，也不存在某台屏单独设型号。一次换型 = 5 台屏同时变。这正是车间的真实情况（一条线同时只做一个型号），也让实现和验证都简单了一个量级。

## 4. 内容模型

> **v2.0.0 已修订本节**：内容宿主由「型号 × 线体工序」改为「机种 × 工位」，
> 并新增「线体设置 / 机种设置 / 工位上传」。原表仍保留作历史依据，最新口径见**第 11 节**。

```
产品型号 Model（如 X200、X300）
  └─ 工序 Process（OP10 / OP20 / OP30 / OP40 / OP50）
       └─ 播放清单 Playlist
            ├─ 图片 ×N（作业指导书，每张停留 N 秒）
            └─ 视频 ×N（播完即下一项）
            整轮循环
```

**规则一：一台屏就是一道工序，换型只换型号。**
屏上没有"工位"这个概念。OP30 那台屏永远显示 OP30 的内容，它的工序不随换型变化；换型时变的是"这道工序现在做哪个型号"。
所以屏的身份 = 工序代码（`OP30`），配置里只填这一个值，不注册、不建档案。

**规则二：同一型号下，每个工序的内容各不相同。**
X200 的 OP10 和 OP30 是两套完全不同的图和视频。内容不是"按型号一套"，而是"按（型号 × 工序）一套"。

以 5 道工序、10 个型号计算，内容总共有 **10 × 5 = 50 套**。

| 型号 \ 工序 | OP10 | OP20 | OP30 | OP40 | OP50 |
|---|---|---|---|---|---|
| X200 | 清单 | 清单 | 清单 | 清单 | 清单 |
| X300 | 清单 | 清单 | 清单 | 清单 | 清单 |
| … | | | | | |

## 5. 换型与遥控切换机制（决定验收能否通过）

### 5.1 切换是"整批原子切换"，不是一台一台换

一次换型 = 服务器发一个型号号 → **5 台屏在同一瞬间整体翻到新型号**。

```
班长点"切换到 X300"
        │
        ▼
  服务器：current_model = X300，seq +1，唤醒所有挂起的终端
        │
   ┌────┴────┬────────┬────────┬────────┐
   ▼         ▼        ▼        ▼        ▼
 OP10屏    OP20屏   OP30屏   OP40屏   OP50屏     ← 同一瞬间，全部翻
 X300      X300     X300     X300     X300
```

**必须一起切的三条理由**（都是车间的真实后果，不是技术洁癖）：

| 不同时切会怎样 | 后果 |
|---|---|
| 逐台下发 | 一小时内 5 台屏新旧混杂，前道按新型号做、后道还按旧型号做，**直接产生批量错件** |
| 逐个工序滚动切 | 中间几十秒里 OP10 已是新型号、OP20 还是旧型号，同样是混批 |
| 边下边播 | 屏上第 1 张是新图、第 5 张还是旧图，工人无法判断自己看的是哪一批 |

所以规则定死：**要么整批全翻，要么一台都不翻。**没有中间状态。

### 5.2 怎么做到"同一瞬间"：等所有人备齐再喊开始

有 5 分钟余量之后，内容可以现场下载，但**不能各下各的、各下完各翻**——5 台网络速度不一样，
快的先翻、慢的后翻，照样是混批。所以切换分两段：

```
班长点"切换到 X300"
   │
   ├─ ① 服务器喊：各班去准备 X300   ──→  5 台屏开始下载，画面照旧播现在的内容
   │                                        （顶栏：准备中 3/11）
   ├─ ② 每台下完 → 举手告诉服务器（我备好了）
   │
   └─ ③ 5 台都举手 → 服务器喊：翻！
                          ──→  5 台屏在同一瞬间换画面，并删掉自己的旧文件
```

**特殊情况：5 分钟到了还有台没举手**

不卡住整条线——服务器直接喊"翻"，没备好的那台屏保持旧内容，顶栏挂**红字** `内容未就绪 · 请勿作业`。
班长在管理端一眼能看到是哪台没跟上，去查那一台的网。

> 两个坏选择都排除了：
> ① 死等 → 一台网络差，全线停 5 分钟以上，停产；
> ② 谁快谁先翻 → 混批，产生错件。
> 取中间：**整线照常切，个别掉队的显式告警**。

### 5.3 切换到底要多久

| 环节 | 耗时 |
|---|---|
| 服务器广播型号号 | 几十字节，**毫秒级** |
| 5 台同时下载本工序一套（约 27MB） | 正常 WiFi **每台 3–6 秒**；网络很差（1Mbps）也只要 **3.6 分钟** |
| 校验 sha256 | 27MB 约 0.2 秒 |
| 翻画面 | 同步替换，**0.1 秒内** |
| **实测目标** | **10 秒内完成**（正常网络） |
| **验收上限** | **5 分钟内完成**（你说的红线） |

**5 分钟这个数意味着什么**：27MB ÷ 300 秒 ≈ **90KB/s 就够了**。
也就是说，只要屏那儿还有能用的 WiFi 信号（哪怕一两格），切换就一定能在 5 分钟内完成。
这比原来"必须 50Mbps"的要求宽松了 50 倍——**采购和布网的压力基本消失**（见 6.6）。

### 5.4 旧文件客户端自己删，不保留

| 项 | 规则 |
|---|---|
| 本地常驻 | **只有 1 套**：当前播放的这个型号 × 本工序，约 **27MB** |
| 什么时候删 | 新型号**下载完、校验通过、画面已翻过去之后**立即删，不等定时任务 |
| 删什么 | 上一型号在**本工序**下的全部本地文件（图 + 视频） |
| 不保留 | 不归档历史型号、不做"回滚到上一型号"的本地快照、不留任何旧副本、**也没有"另一套"可以误播** |
| 服务端配合 | 服务端媒体是**内容寻址、多型号共用**的，只在无人引用时才清理（`/api/media/gc`），与终端删除互不影响 |

**只有 1 套是最彻底的做法**：盘上任何时候都只有当前该播的东西，不存在第二套内容，
也就不存在"切换时翻错槽""旧内容偷偷占着盘"这类问题。代价只是切换要等几秒下载——而这个代价你已经允许了。

> **一个必须承认的限制**：断网时切不了型号（内容还没下下来）。
> 但这在物理上本来就成立——服务器和终端走同一个 AP，AP 断了终端根本收不到切换指令。
> 所以"断网时仍能响应切换"这件事在无线架构下没有实际场景，真正要保住的是**断网时画面不中断**（见 A4）。

### 5.5 内容不全时怎么办（工程部没做完）

车间不能因为工程部漏了一张图就停产，所以**允许切换**，但必须让人看见：

- 新型号本工序内容**缺项** → 照切，缺的那几项跳过不播
- 顶栏常驻橙色标记 `内容不全 8/11`
- 管理端型号列表里该型号标红

**不允许**的是"静默降级"——屏上看着正常、实际少了两张关键图，比直接报错危险得多。

### 5.6 终端上的可见状态

屏幕顶栏一行字：`X300 / OP30`，右下角小字 `第 2 张 / 共 7 张`。
工人一眼能确认"我播的是不是这批货"——在 19 寸屏上，这行字必须够大（≥28px），不能做成装饰性小字。

异常状态也用顶栏表达，且**必须让 1 米外站着的人看见**：

| 状态 | 顶栏显示 | 颜色 |
|---|---|---|
| 正常 | `X300 / OP30` | 白 |
| 离线 | `X300 / OP30 · 离线` | 灰（不打扰） |
| 内容不全 | `X300 / OP30 · 内容不全 8/11` | **橙** |
| 切换准备中 | `正在切换到 X400 · 3/11`（画面仍是旧内容） | **蓝** |
| 掉队未就绪 | `内容未就绪 · 请勿作业` | **红 + 闪烁边框** |

异常状态也用顶栏表达，且**必须让 1 米外站着的人看见**：

| 状态 | 顶栏显示 |
|---|---|
| 正常 | `X300 / OP30`　（白字） |
| 离线 | `X300 / OP30 · 离线`　（灰底小标记，不打扰） |
| 内容不全 | `X300 / OP30 · 内容不全 8/11`　（**橙色**） |
| 切换准备中 | `正在切换到 X400 · 3/11`　（**蓝色**，此时画面仍是旧内容） |

## 6. 屏幕基线（D5 = 19 寸，本次修订的核心）

### 6.1 先说一个必须先解决的冲突

原方案按 42–55 寸、观看 3 米写的。**19 寸放在 3 米外，图上细节是看不清的**，这不是调字号能救回来的：

| 距离 | 19 寸屏的视角宽度 | 相当于 | 判断 |
|---|---|---|---|
| 1.0 m | 21.3° | 42 寸屏在 2.2 m | 舒适，接近 1:1 像素 |
| 1.2 m | 17.9° | 42 寸屏在 2.6 m | **推荐** |
| 1.5 m | 14.3° | 42 寸屏在 3.3 m | 可接受下限 |
| 3.0 m | 7.2° | 42 寸屏在 6.6 m | **不可用**：单像素视角 0.34′，低于人眼 1′ 分辨力，等于分辨率被"抹掉"一半 |

19 寸 5:4 面板可视区 **376.9 × 301.5 mm**，1280×1024 时像素间距 **0.294 mm**。
按 1′ 视觉分辨力反算：**距离超过 1.5 米，1 像素就看不见了**——指导书上的螺丝孔位、线束走向这类细节正好是 1–3 个像素宽。

**结论（R1 已核实）：显示器放在工作台上，观看距离 1.0 米 —— 19 寸成立，且余量充足。**

1.0 米处视角 **21.3°**，相当于 42 寸屏在 2.2 米，是这类看板最舒服的区间；单像素视角 **1.01′**，正好落在人眼分辨力上，
意味着**屏上 1 个像素对应眼睛能分辨的 1 个点，分辨率没有浪费也没有不足**——1280×1024 就是这台机器的正确分辨率，不需要 1080p，也不该降到 1024×768。

原来担心的"3 米看不清"不成立，A7 可以按 1.0 米验收。
但仍有一条边界要守住：**工作台距离改成 1.5 米以上（例如操作工要退后取料）时，细节就开始糊**，屏必须留在伸手可及的范围内。

### 6.2 版式（5:4 单列，不做左右分栏）

5:4 接近方形，左右分栏会让两边都变窄（各 620px），字和图都挤。定为**单列纵向**：

```
┌──────────────────────────────┐ 1280
│ 顶栏 88px  X300 / OP30   时间 │
├──────────────────────────────┤
│                              │
│        主区（图片/视频）        │ 约 780px
│                              │
├──────────────────────────────┤
│ 底栏 120px  第 2/7 张 · 进度点 │
└──────────────────────────────┘ 1024
```

- 图片**满宽显示**（1280×1024 或 4:3 构图的图，几乎占满屏）
- 视频 16:9 时 → **上下留边，不裁切**（1280×720，上下各 152px，用深灰 #1a1a1a 填，不用纯黑）
- 一条视频独占一屏，不在同一屏里塞图和视频

### 6.3 字号（按 1.2 米观看反算，不是拍脑袋）

按"舒适阅读 = 2 倍最小可辨高度"：

| 用途 | 最小字号 | **实际取值** | 说明 |
|---|---|---|---|
| 顶栏型号/工序 | 14px | **32px** | 抬眼看一眼就能确认 |
| 图片内文字 | — | 图内字号由工程部出图控制，**出图时按 1.2 米验看** | 见 6.4 |
| 底栏页码 | 14px | **28px** | |
| 警示/红线提示 | 18px | **36px + 色块 + 图标** | 不靠颜色单独表达（色弱） |

对比度 ≥4.5:1，禁用纯红大面积底色（久看刺眼、长时间静态会残影）。

### 6.4 图片与视频规格（工程部按此出，否则屏上必糊）

| 项 | 规格 | 为什么 |
|---|---|---|
| 图片尺寸 | **1280×1024（5:4）或 1024×768（4:3）** | 16:9 截图投到 5:4 屏上，上下各浪费 152px，实得只有 25% 面积 |
| 图片格式 | JPEG，质量 85，**单张 ≤400KB** | 50 套 × 10 张 = 500 张，按 400KB 共 200MB，可接受 |
| 图片内字号 | 图上标注文字**高度 ≥24px**（按 1280 宽出图） | 缩放到屏上后仍 ≥1′ 视角 |
| 视频分辨率 | **1280×720**，H.264，≤3 Mbps | 屏只有 1024 高，1080p 是纯浪费；720p 在 19 寸上肉眼无差 |
| 视频时长 | **不限制，改按体积管**（v1.6.0 修订，原为单段 ≤60 秒） | 见下方说明 |
| 视频大小 | **单套内容合计 ≤120MB**（含图片） | 5 台并发下弱网仍需在 5 分钟内下完 |
| 禁止 | 手机竖拍、带水印、屏幕录制带鼠标 | 竖拍在 5:4 屏上只剩中间一条 |

> **v1.6.0 修订：视频时长不再设 60 秒上限。**
> 60 秒是早期拍的数，实现里从来没有硬限制（视频是 `onended` 播完进下一项）。
> 真正决定换型快慢的是**字节数**而不是时长：同样 3 分钟的视频，1Mbps 和 8Mbps 差 8 倍体积。
> 现在界面在清单里实时显示"合计体积 / 预计换型耗时（内网、WiFi 两档）"，
> 建议单套 ≤120MB —— 5 台 × 120MB = 600MB，千兆内网约 24 秒，
> 车间 WiFi 20Mbps 约 4 分钟，仍在 5 分钟窗口内。超了不拦，只标黄标红。
>
> 页面顶部还新增了 **PDF 直接上传**（服务端按页拆成图片）与**每项图片显示方式**
> （适应·不裁 / 铺满·裁边 / 缩放 50%–200%），详见 `CHANGELOG.md` v1.6.0。

### 6.5 硬件（D1 = exe + Windows 迷你主机，已定）

| 项 | 要求 | 说明 |

| CPU | Intel N100 / N150（4 核，TDP 6W） | 硬解 720p/1080p 无压力 |
| 内存 | **8GB 起，建议 16GB** | N100 单通道单插槽，后期加不了 |
| 存储 | **256GB NVMe SSD 起** | 终端常驻仅约 54MB，128GB 也够，但 256GB 不贵，留出系统更新余量 |

| 视频输出 | HDMI 2.0 | 接 19 寸显示器 |
| 系统 | Windows 11 专业版 | 需能关闭自动更新 |
| 功耗 | 10–15W | 全年电费约 60 元 |

| 型号 | 配置 | 参考价 | 备注 |
|---|---|---|---|
| **铭凡 UN100D**（推荐） | N100 / 16GB / 512GB / Win11 | ≈ ¥1519 | 双 2.5G 网口，开箱即用。默认网卡 AC 9560 = WiFi 5，**现在够用，不必换 AX210** |
| 铭凡 UN100D 低配 | N100 / 8GB / 256GB | ≈ ¥1199 | 同样不必换网卡 |
| 零刻 EQ12 | N100 准系统 | ≈ ¥800 | 自配 8GB + 256GB（约 +¥250） |
| 极摩客 G3 | N150 准系统 | ≈ ¥699 | 金属机身，散热好，同样自配 |

**19 寸显示器要盯的三件事**（比主机更容易忽略）：

1. **分辨率必须是 1280×1024**。少数 19 寸标 1366×768，那是 16:9 面板，版式要重做，采购前看清楚。
2. **接口要是 HDMI 或 DP**。老工业屏只有 VGA 时，加一个 HDMI→VGA 转接（约 ¥30），并把分辨率锁在 1280×1024@60。
3. **面板优先 IPS**。19 寸工业屏大量是 TN，工人站着从上方看会整片发灰、颜色反转——这一点在样机上必须亲眼验证。

其余：亮度 ≥250 cd/m²（车间照明强选 350）、雾面不反光、VESA 75/100 孔位、宽温 0–50℃。

**"放在工作台上"带来的三条额外要求**（1 米距离才有的问题，3 米时不存在）：

| 项 | 要求 | 不做的后果 |
|---|---|---|
| **仰角** | 屏面**上仰 10–15°**，屏幕中心略低于人眼（约 1.25–1.35m 高） | 屏平放台面上时，站着看是斜视 40°+，TN 面板会整片发黑，IPS 也会掉对比度 |
| **防眩光** | 必须**雾面**，且避开顶灯正下方（或加遮光罩） | 1 米距离时顶灯在屏上形成的高光斑正好盖住图面中间，看图全废 |
| **防护面** | 加 **3mm 亚克力或钢化玻璃面板**，边框密封 | 工作台上工人拿零件、工具、扳手，磕碰和油污落在屏上是必然事件 |

另外，1 米距离意味着**屏就在手边**——必须确认这台机器不带触摸功能，避免工人误触（一期不做触摸交互，见第 8 节）。

### 6.6 无线网络部署参数（5 分钟时限后大幅放宽）

| 项 | 要求 | 原因 |
|---|---|---|
| 频段 | **只走 5GHz** | 车间变频器、伺服、对讲机、无线扫码枪全在 2.4GHz。这条不放宽：不是带宽问题，是干扰导致**断流** |
| 协议 | 802.11ac（WiFi 5）起 | WiFi 6 更好但非必需 |
| 信道 | 149/153/157/161，带宽 40MHz | 5 台用不到 80MHz，40MHz 更抗干扰 |
| 单台实测 | 在屏所在位置测到 **≥1Mbps 下行**（原要求 50Mbps） | 90KB/s 就能在 5 分钟内下完 27MB，1Mbps 留了 10 倍余量 |
| **更该测的** | **连续 10 分钟不断流** | 下载中途掉线比速度慢更要命——会触发重试，反而更久 |
| AP 数量 | 5 台屏集中 → 1 台；跨度 >30m 或有承重墙 → 2 台 | 不变：取决于覆盖，不取决于带宽 |
| 服务器 | 走**有线**接 AP | 唯一数据源不能无线 |
| SSID | 单独一个，不与办公网共用；能关 2.4G 就关 | 防止终端漂到 2.4G（漂过去就容易断流） |

**要求性质变了**：原来要"快"，现在只要"稳"。所以采购重点从"挑 WiFi 6 网卡、算并发带宽"
变成"**把信号覆盖到工位、别让终端掉到 2.4G**"——后者是布点问题，不用花钱。

### 6.7 体积与带宽（按 19 寸规格 + "本地只留 1 套"重算）

| 项 | 计算 | 结论 |
|---|---|---|
| 单套内容（一个型号 × 一道工序） | 10 图 × 0.4MB + 1 视频 22.5MB（720p/3Mbps/60s） | **约 27MB** |
| **服务器总库** | 50 套 × 27MB | **约 1.4GB**（只存在服务器上） |
| **单台终端常驻** | 只有当前 1 套 | **约 27MB** |
| 一台终端首次装机 | 27MB，正常 WiFi | **约 5 秒** |
| 换型（5 台同时下） | 每台 27MB，正常 WiFi | **每台 3–6 秒** |
| 换型（验收红线） | 300 秒内下完 27MB | 只需 **90KB/s** |

**关键推论：网络要求从 50Mbps 降到 90KB/s。** 这是这次放宽时限带来的最大意外收获：

| 原来（10 秒切换） | 现在（5 分钟切换） |
|---|---|
| 必须 50Mbps，得挑 WiFi 6 网卡、精心布 AP | **90KB/s 即可**，WiFi 5 都绰绰有余 |
| 铭凡 UN100D 默认 AC 9560（WiFi 5）不够，**必须换 AX210** | **不用换**，省 ¥100/台 + 拆机风险 |
| AP 位置要实测 5 台并发，可能要多买一台 | 一台老 AP 就够，重点变成"信号覆盖到工位"而不是"带宽够不够" |

> 注意区分两件事：**播放**用的是本地文件，与网络无关；**网络只影响下载/切换那一小段**。
> 所以网络从"必须很快"变成"必须能连上、别断"——这是一个性质完全不同的要求，好满足得多。
> 服务器端 1.4GB 是**内容寻址、型号间去重**后的量级——同一张标准图被 6 个型号引用时只存一份，实际通常小于这个数。

## 7. 验收标准

| # | 标准 | 怎么测 |
|---|---|---|
| **A1** | **服务端切换型号，5 台屏 5 分钟内全部变成新内容；正常网络下应 10 秒内完成；最先变与最后变的间隔 ≤1 秒** | 5 台屏摆一排用一台手机同时录，回放看时间戳。三个数分别代表：切得动、切得快、切得齐 |
| A2 | 切换过程不黑屏、不闪白、不回到桌面 | 录像回看 |
| A3 | 拔掉 AP，5 台屏画面不中断、循环正常 | 断网 30 分钟看画面。**注意：断网时不测切换**——服务器也在同一个 AP 后面，断网时终端根本收不到切换指令，这个场景不存在 |
| A4 | 断网 8 小时，播放不中断、不卡顿 | 夜间断网，第二天看 |
| A5 | 单台断电重启，自动回到当前型号继续播，不需人操作 | 直接拔电源 |
| A6 | 一台全新机器从装机开机到播出正确内容 ≤5 分钟 | 拿一台没配过的迷你主机，填两行配置，掐表到画面出现 |
| **A7** | **在 1.0 米处（工作台实际观看距离），能看清指导书图上 2mm 的特征** | 拿游标卡尺量一个实物特征，站屏前看，与实物比对 |
| **A8** | **切换成功后，上一型号的本地文件确实被删除** | 切换后进终端目录看：**只剩 1 套**，旧型号文件数为 0；连续切 3 次，目录大小始终约 27MB、不增长 |
| **A9** | **单屏内不存在半新半旧** | 切换时盯着任意一台屏：要么整屏是旧内容 + 顶栏"准备中"，要么整屏是新内容，**不允许一屏里混两个型号的图** |
| **A10** | **掉队的那台会被看见** | 把某台的 WiFi 信号压到极弱（或直接拔那台的网卡），让它下不完；5 分钟到期后：其余 4 台正常翻新，掉队那台**顶栏红字"内容未就绪 · 请勿作业"**，管理端能指出是哪道工序 |

**A1 和 A7 过了，这套系统就算立住了。** A8 / A9 是"一起切、不留旧"这两条纪律的可验证形式，缺了就等于没做。

> A7 的判据必须是"能不能看清 2mm 特征"，而不是"字大不大"——指导书的价值在细节，字大而细节糊等于没用。

## 11. v2.0.0 修订（2026-10-27）

### 11.1 用户新提的两条需求（原文）

1. 作业内容调整为显示有那几条线，每条线做那个机种，换型，显示那些客户端完成切换
2. 增加线体设置，机种设置，机种中有工位设置，每个工位可以设置上传的 pdf、图片和视频

补充确认：**作业内容实际上是总览，下面是各项的设置。**

### 11.2 由此确定的口径

| 项 | 一期原口径 | v2.0.0 口径 |
|---|---|---|
| 播放内容挂在 | 型号 × 线体工序 | **机种 × 工位**（全厂一份，跨线共用） |
| 线体工序管什么 | 既有"几块屏"又有"播什么" | **只管"这条线有几块屏"** |
| 工位 | 明确不做（"屏上没有工位概念"） | **做**，但只是机种里的**内容槽位**，不是设备档案：没有 IP、没有终端注册、没有逐台设置 |
| 允许的文件类型 | 全局按图片/视频/PDF 放开 | **每工位单独勾**（`station_req` 有行 = 允许） |
| 作业内容页 | 型号 × 工序 矩阵 + 清单抽屉 | **线体总览**：几条线、各做什么机种、换型、哪几台客户端切完了 |
| 配置库 | v1.8.0 新增的 `profile` 模板层 | **退役**（"该交什么"由工位自己的要求表达） |
| 工位与线体的关系 | — | **工序码对位**（线体 OP10 ↔ 机种 OP10），不建关联表 |

**没变的（继续有效）**：终端身份是 `线体 + 工序`；换型按线体整体切、两段式（prepare → ready → activate）、
5 分钟超时强切且掉队可见；本地只留一套、旧内容切完即删；一期无权限、无工单。

### 11.3 界面结构（左栏）

```
作业内容        ← 总览：线体 / 当前机种 / 换型 / 客户端切换状态
── 设置 ──
线体设置        ← 建线、启停线、维护工序（这条线有几块屏）
机种设置        ← 建机种、进工位、逐工位上传 PDF / 图片 / 视频
媒体库          ← 查文件、清理未引用
终端监控        ← 各屏 IP / 分辨率 / 磁盘 / 进度
系统            ← 版本、地址、数据目录
```

**总览页与设置页分工**：日常只开总览（看状态、点换型），配置改动一律去设置页，
避免在总览页误改配置。

### 11.4 数据迁移

老库（`item.process_id`）启动时自动迁到 `item.station_id`，按 `(机种, 工序码)` 把两条线的重复内容合并成一份。
升级前必须备份 `data\`；回滚要连库一起回（详见部署手册）。
