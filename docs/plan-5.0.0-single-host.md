# 5.0.0 简化方案：线头主机（单线发布站）

> 2026-11-16 · 基于 4.5.2 现状分析。版本号按 Frank 指定记为 **5.0.0**
> （主版本升级由用户点头，符合版本规则；分阶段开发期间本地迭代仍按末位递增）。

## 一、新定位：一台主机只做一件事

**生产线头放一台主机，唯一职责：把本线各工序要播的内容（视频 + VWI）发布到线上那排屏。**

### 主机职责边界（保留）

| 职责 | 说明 |
|---|---|
| 内容管理 | 机种（产品）× 工序 两级模型不变；每道工序挂视频 / 图片 / PDF（自动拆页） |
| 内容上传 | 选机种 → 选工序 → 传文件；同名不覆盖、sha256 校验、按 `media/<机种>/<工序>/` 落盘 |
| 按工序发布 | 「播放内容」勾选（图/PDF/视频）、播放方式（循环/播完停）、每项停留秒数与显示方式 |
| 当前机种 | 一键切换"本线现在生产哪个机种"，全线屏跟着换 |
| 屏监控 | 看到每块屏：在线 / 计算机名 / 自报工序号 / 播什么 / 内容版本，同工序冲突红标 |
| 局域网服务 | 一个入站 TCP 8092，屏主动连；本机不需要开任何别的端口 |

### 职责边界外（本次砍掉 / 简化）

多线体管理与线体总览、线体 Excel 五页、换型两段式协商（prepare/举手/强翻）、
管理端改写屏配置的指派下发、生产输入 / 生产概况 / 工时与线平衡率、
「按工序 / 按客户端」双视图、批量导入里的线体清单页。

**依据**：单机单线后，"线体"只剩一条，线体维度上的所有管理动作都退化成一次装机配置；
换型协商是为"几十台屏不能各播各的"设计的，单线 15 块屏直切即可；
生产台账与"发布"无关，是另一套需求。

## 二、发布流程（简化后）

1. **装机（一次）**：主机放线头开机 → 每块屏装 ESOP-Client.exe，只填两样：
   服务器 IP + 工序号（不再填线号，也不存在"选哪条线"）。
2. **配内容（日常）**：选机种 → 工序列表 → 传视频 / PDF / 图片 → 保存。
   保存即推送（见下节），屏几秒内换内容。没传内容的工序屏上显示"暂无指导书"。
3. **换型（每天）**：点「切换机种」→ 选产品 → 落库即生效，全线屏 ≤5 秒内换内容
   （取决于每块屏要下载多少 MB，千兆网 25 屏约 5~6 秒）。
4. **日常巡检（可选）**：屏监控一页看全线：哪台掉队、哪台报错号、哪台内容不全。

## 三、推送系统设计

**架构保留**（这套已经实测过硬：改内容到屏 0.1 秒、25 台心跳 P95 20-26ms、25×22MB 千兆 5-6 秒）：

```
管理端保存/切换
    → notifyContentChanged() → contentRev + 1
    → bump() 唤醒所有挂着的长轮询
    → 屏 /api/state?since=旧rev 立即返回
    → 屏 GET /display/playlist?op=自己工序号
    → 逐项下载、sha256 校验、落 content/current/
    → 指纹(fpOf)变了才 flipTo 翻屏；没变只记版本号不闪屏
```

**触发方式收敛为 3 个**（全部走同一个 `notifyContentChanged()`）：

| 触发 | 动作 | 效果 |
|---|---|---|
| 工序内容保存 | `PUT /api/processes/:id` / `PUT /api/playlist`（items/reqs/playKinds/playMode 任一变化） | 该工序的屏 0.1 秒内更新 |
| 切换机种 | `POST /api/board/current` | 全线屏换播新机种内容 |
| 批量导入完成 | 工序参数导入（有变化时） | 涉及工序的屏更新 |

**单机单线带来的简化**：

- `contentRev` 全局一个值（不再有"线体级"概念）；无关工序变更靠指纹避免闪屏，这条不能省
- `/display/playlist` 去掉 `line` 参数（终端也不带）；`/api/state` 去掉 `line` query
- 删 `/api/ready` 举手：没有换型协商，屏是否就绪由 5 秒心跳里的"当前播的机种 / 内容版本"体现
- 删指派联动推送（绑定/解绑推 rev 那套随 client_bind 一起消失）
- 保留 4.5.2 刚修好的语义：清单被「播放内容」全排除 → 屏清屏显示"共 N 项被排除"

**屏侧反馈（掉队检测）**：心跳 5 秒上报 `计算机名 / 自报工序 / 正在播的机种+内容版本 / 在线`。
管理页拿它和主机当前的 `contentRev` 对比：落后就标"同步中"，差得多标红"掉队"。

## 四、与现有方案（4.5.2）的差异点

| # | 现有（4.5.2） | 5.0.0 | 处理方式 |
|---|---|---|---|
| 1 | 多线体：11 条线、状态机、线体总览、slots | 一条"本线"，装机时定一次 | line 表**保留表结构**（老库平滑），只认第一条；界面改「本线设置」 |
| 2 | 线体 Excel 五页 | 单页「工序参数」可导回 | 删五页文件与路由，`import.js` 保留工序参数部分 |
| 3 | 换型两段式：prepare → 举手 → activate → 强翻 5 分钟 | 直切：落库即生效 | 删 `switch.js` 协商状态机、`/api/ready`、deadline、maybeActivate；保留 `setCurrentModel` |
| 4 | 指派体系：client_bind 唯一约束、hello 四态、管理端改写屏 config | 屏自报 + 冲突红提示 | 删 client_bind / applyAssignment / 终端 applyAssign；client 心跳台账保留 |
| 5 | 终端带 `?line=`、cache 记 lineCode | 只认工序号 | 终端删 line 逻辑；老 config.json 里的 line 字段**忽略不报错** |
| 6 | 终端监控：按工序 / 按客户端两视图 | 单视图（全线一张表） | 合并，默认即唯一视图 |
| 7 | 生产输入 / 生产概况 / 工时 / 线平衡率 | **建议砍**（待拍板） | 砍入口与导航；`prod_input` 表与数据保留在库里不动，回退容易 |
| 8 | 机种×工序、媒体、PDF 拆页、播放内容勾选 | **原样保留** | 这是核心，一行不动 |
| 9 | contentRev 长轮询分发、sha 校验、指纹翻转 | **原样保留**（去线体参数） | 已验证的底座 |
| 10 | 全量 Excel 导入（机种/工序） | 保留，按单线口径 | 首次导入仍一次进 1107 机种没问题 |

**终端契约变化**：`?line=` 不再使用（存在则忽略）；`/api/state` 不再有 assign 字段；
其余（hello→简化为登记、telemetry、/display/playlist 主体字段）兼容。

**数据兼容**：老库（含 4.5.2 交付库）直接启动，不需要迁移工具；client_bind 表留在库里但不再读写。

**回滚**：5.0.0 与 4.5.2 程序文件 + data 可互换（表结构不删只停用），回滚换回 4.5.2 exe 即可。

## 五、分阶段修改计划

> 每阶段独立可验收、可回滚；阶段内按末位升版本号（4.5.3、4.5.4…），全部完成后统一出 **5.0.0**。

### 阶段 1：单线化（数据与界面）

- **目标**：主机只认一条线；所有界面去掉线体维度
- **模块**：`src/db.js`（取"本线"的工具函数）、`src/api/catalog.js`（lines 路由收成本线设置）、
  `src/api/linesSheet.js`（删五页）、`src/api/display.js` / `router.js`（去 line 过滤）、
  `public/`（线体总览 → 本线设置；运行产线行简化）、`src/api/export.js`
- **验收**：全新空库装机流程走通（不再选线）；交付库启动自动以第一条线为"本线"；
  工序参数 Excel 导入导出可用；界面导航无"线体"页

### 阶段 2：换型直切

- **目标**：点「切换机种」落库即生效，全线屏 ≤5 秒换内容；无"准备中"中间态
- **模块**：`src/switch.js`（删协商状态机）、`src/api/board.js`（switch 并入 current）、
  `src/api/state.js`（去 pending/phase）、`terminal/src/sync.js`（删 prepare 分支与举手）、
  `src/api/clients.js`（hello 简化）
- **验收**：切换后屏按下载量换内容；拔网半小时的屏插回来自动"补播"（stale→自愈）；
  两机联调套件（test/two-pc.mjs）改写后全过

### 阶段 3：屏监控简化

- **目标**：一页看清全线屏；同工序冲突红提示；不再改写屏配置
- **模块**：`src/api/clients.js`（删 client_bind 相关路由）、`src/db.js`（delClient 简化）、
  `public/app.js`（监控单视图 + 冲突红标）、`terminal/main.js`（删 applyAssign）、
  `terminal/src/sync.js`（删 checkAssign）
- **验收**：两台屏报同一工序号 → 管理页红标"冲突"；屏坏换新机、填同样工序号即接上，
  服务端零操作；删除按钮保留（清死记录）

### 阶段 4：外围裁剪（待拍板后执行）

- **目标**：导航只剩「内容发布 / 屏监控 / 系统设置」三块
- **模块**：`src/api/prod.js`、`public/` 生产输入与概况页、首页总览简化
- **验收**：主界面无生产入口；库里 prod 数据原样保留；4.5.2 回滚可正常显示生产页

### 阶段 5：终端瘦身 + 5.0.0 出版

- **目标**：终端去 line/assign 逻辑，出新包，完整交付
- **模块**：`terminal/`（config.js、sync.js、cache.js、main.js、renderer）、打包、
  `09.ESOP/v5.0.0/` 交付目录、CHANGELOG、装机说明、tag `v5.0.0` + GitHub Release
- **验收**：隔离库全链路测试（empty-playlist / link-test 改写后全过）；两台真机联调；
  交付目录齐（两 exe + zip + SHA256SUMS + 装机说明）；收尾五步走完
