# 部署手册 · ESOP 发布系统 v2.0.0

> 面向：把服务端和 5 台终端装到线上的人。
> 目标：**从拿到 exe 到屏上出正确内容，一台不超过 5 分钟**（A6 实测 10.3 秒首装、6.96 秒开机）。

---

## 0. 服务端先装在哪（只要一台）

服务端是**桌面程序**：双击一个 exe，服务和界面一起起来。**不装 Node.js、不用管理员权限、不用浏览器。**

| 文件 | 说明 | 大小 / 校验 |
|---|---|---|
| `server-gui/dist/ESOP-Server.exe` | **服务端整包（v2.0.0）**，单文件免安装 | 93 MB 级<br>校验见交付目录 `SHA256SUMS.txt` |
| `terminal/dist/ESOP-Client.exe` | 终端接收端（v1.7.1），**单文件免安装**，5 台各一份 | 69.8 MB<br>校验见交付目录 `SHA256SUMS.txt` |
| `docs/a7-检验卡-1280x720.png` | A7 可读性检验卡，现场用 | 65 KB |

### 服务端装机三步

1. 把 `ESOP-Server.exe` 放到 `D:\ESOP-Server\`（**路径用纯英文、不要空格**）。
2. **双击它**。窗口打开就是管理界面，同时 `D:\ESOP-Server\data\` 目录自动建好。
3. 点顶栏的 **「系统」** 按钮，里面有**终端装机要填的服务端地址**（形如 `http://192.168.x.x:8092`），
   点「复制」存下来，装 5 台终端时逐台粘贴。**不要填 127.0.0.1**，那是服务端自己看到的地址。

顺手做两件事：

- **开机自启**：在「系统」面板里打开开关（或右键托盘图标勾选）。只写当前用户，不需要管理员。
  自启后静默进托盘、不弹窗口 —— 这是常驻服务的正常表现。
- **防火墙**：第一次启动 Windows 会弹「是否允许访问网络」，勾「专用网络」允许。
  没弹或被拒了，用管理员 cmd 执行一次：
  ```
  netsh advfirewall firewall add rule name="ESOP-Server 8092" dir=in action=allow protocol=TCP localport=8092
  ```

服务端的数据全在 exe 同级的 `data\`（数据库 + 工程部上传的图片视频 + `server.log` 日志）。
**备份就备份这个文件夹**；换机器时连整个文件夹一起拷过去。

### 关窗口 ≠ 关服务（一定要知道）

双击 exe 后，右下角托盘会多一个图标。

| 你做的操作 | 会发生什么 |
|---|---|
| 点窗口右上角 **X** | **窗口消失，服务继续跑**，缩到托盘里，5 台终端照常工作 |
| 双击托盘图标 / 右键→显示管理界面 | 窗口重新出现 |
| 右键托盘 → **退出服务端** | 真的停止，5 台终端全部掉线（有终端在线时会二次确认） |

这是刻意设计：服务端是产线的核心，误关一次窗口就断线，代价太大。
所以**找不到窗口时去托盘找，不要重复双击 exe**（重复双击只会把已有窗口唤回来，不会开出第二个服务）。

### 出问题了先看日志

`D:\ESOP-Server\data\server.log` 双击就能用记事本打开（已带 UTF-8 BOM，不会乱码）。
「系统」面板里有「定位」按钮直接跳过去。超过 2 MB 自动改名成 `server.log.1`。

<details>
<summary>无图形界面 / 远程桌面场景：改用绿色免安装包</summary>

服务端如果是远程桌面、或者不希望桌面上出现窗口，用绿色包：
`release/online-vwi-server-1.4.0-win-x64.zip` 解压到 `D:\ESOP-Server`，双击 `启动服务端.bat`，
再用浏览器开 `http://服务器IP:8092/`。附带 `停止服务端.bat`、`设置开机自启.bat`、`取消开机自启.bat`；
英文版 Windows 另有 `start-server.bat` 等英文脚本。

**两种形态功能完全一致**（共用 `src/server-core.js`），只是入口不同：桌面版是「服务+界面一个 exe」，
绿色包是「服务脚本 + 浏览器访问」。
</details>

## 1. 交付物

| 文件 | 说明 | 大小 / 校验 |
|---|---|---|
| `server-gui/dist/ESOP-Server.exe` | **服务端桌面程序（现场用这个，v3.5.0）** | 93 MB 级 |
| `terminal/dist/ESOP-Client.exe` | 终端接收端（v1.7.1），单文件免安装 | 69.8 MB |
| `release/online-vwi-server-1.4.0-win-x64.zip` | 服务端绿色包（无图形界面时用，旧版 1.4.0） | 31.8 MB |
| `docs/a7-检验卡-1280x720.png` | A7 可读性检验卡，现场用 | 65 KB |

> exe 每次启动会自解压到 `%TEMP%\esop-client` 再运行，所以**第一次启动慢 2–3 秒**，之后就稳定在 7 秒左右。

### 从旧版升级（服务端 1.5.0 / 终端 1.6.0 → 本版）

这一版把产品名从「在线VWI」改成 **ESOP**，exe 固定叫 `ESOP-Server.exe` / `ESOP-Client.exe`。
**代码会自动迁移，不用重装**，但下面几件事必须知道：

| 项 | 旧 | 新 | 要不要人工处理 |
|---|---|---|---|
| 服务端目录 | `D:\VWI-Server\` | `D:\ESOP-Server\` | 不用。老机器留在原目录照样跑，文档按新目录写；想统一就把**整个文件夹**改名，`data\` 一起走，别只搬 exe |
| 终端目录 | `C:\VWI\` | `C:\ESOP\` | 同上。**开机自启项写的是 exe 绝对路径**，目录改了要重新打开一次「开机自启」 |
| 终端配置目录 | `%LOCALAPPDATA%\online-vwi-terminal\` | `%LOCALAPPDATA%\esop-client\` | **不用**。首次启动自动迁移（含 content 缓存），地址与工序全部保留；迁移结果记在 `logs\terminal.log` 的 `[config]` 行 |
| 开机自启项名 | `com.frank.online-vwi-terminal` | `com.frank.esop-client` | 旧注册表项不会自动清。建议升级后把「开机自启」关一次再打开，并确认 `HKCU\...\Run` 里没有残留的 `online-vwi` 项 |
| 防火墙规则名 | `VWI-Server 8092` | `ESOP-Server 8092` | 只是名字，旧规则继续有效；重命名可选 |
| 服务端数据库 | `data\vwi.db` | **仍然是 `vwi.db`** | 故意不改：这个文件名用户看不到，改它只多一次数据迁移的风险 |
| 终端日志/缓存 | `%LOCALAPPDATA%\online-vwi-terminal\logs\` | `%LOCALAPPDATA%\esop-client\logs\` | 跟着配置目录一起迁 |

**回滚**：换回旧 exe 即可。服务端库只新增过表，旧版读它会忽略不认识的表；
终端若已迁移到 `esop-client`，回滚前把该目录改名回 `online-vwi-terminal`，否则旧版会当成"没装过"、弹装机向导。


### v2.0.0 升级（服务端 1.10.x → 2.0.0，**必读**）

这一版是**主版本**，数据模型变了：播放内容从「型号 × 线体工序」搬到「机种 × 工位」。
**老库启动时自动迁移，不需要清库、不需要重录内容**，但有两件事必须做：

1. **升级前先把 `data\` 整个目录复制一份**（含 `vwi.db` 与 `media\`）。
   迁移是就地改表结构（关外键 → 建新表 → 搬 → drop 老表 → rename），
   成功与否都要有退路。
2. **终端不用动**。`/display/boot` 与 `/display/playlist` 的入参出参没变，
   现场 5 台屏（1.7.x）换掉服务端就能直接跑，不改 `config.json`、不重装。

升级后第一次启动，日志里会有一行：

```
[db] 41 条播放内容已从「线体工序」迁到「机种工位」
```

数字对得上就是迁完了。进「媒体库」逐个机种看一眼，工位里应该能看到原来的图片/视频。

**回滚要连库一起回**：2.0.0 之后 `item` 表已经没有 `process_id` 列，
换回 1.10.x 的 exe 会读不到内容（不是报错，是"什么都没配"）。
回滚 = 旧 exe + 升级前备份的 `data\`，两个一起换回去。

### v3.0.0 升级（服务端 2.0.0 → 3.0.0，**必读**）

这一版也是**主版本**：工位多了线体维度，内容从「机种 × 工序码」变成「机种 × 线体 × 工序码」。
原因是现场同一个机种会在不同线上做，而两条线的工序编码完全不同 —— 一套内容全厂共用不成立。

**升级前必须做的一件事：把 `data\` 整个目录复制一份**（含 `vwi.db` 与 `media\`）。
理由同 2.0.0：迁移是就地改表结构。

**升级后第一次启动，日志里会出现这一行**（`data\server.log`）：

```
[db] 工位已按线体拆开：50 个工位 → 100 个，内容 6 条已复制到各线
```

`M > N` 是**正常的**，不是重复插入。原因：2.0.0 的工位表里没有线体信息，
还原不出"原本属于哪条线"，所以策略是 **复制到所有含同名工序码的线体，一条都不丢**。
迁完请进「媒体库」按线过一遍，把不该有内容的那条线删掉即可。

如果是从 **1.x 直接跳到 3.0.0**（中间没装过 2.0.0），日志会是这两行，
而且**内容会按原工序所属线体精确归位**，不会复制：

```
[db] 41 条播放内容已从「线体工序」迁到「机种 × 线体 × 工位」
[db] 已按线体工序补上 80 个机种工位
```

**终端不用动**：`/display/boot`、`/display/playlist` 入参出参没变，
现场 5 台屏（1.7.x）换掉服务端就能跑，不改 `config.json`、不重装 exe。
只是 `stationOf()` 内部多用了 `line.id`，对外表现完全一样。

**回滚要点（比 2.0.0 更严格）**：3.0.0 之后 `station` 表有 `line_id`、唯一键也变了，
换回 2.0.0 的 exe 会**读不到工位**（不报错，界面显示"什么都没配"）。
回滚 = **旧 exe + 升级前备份的 `data\` 一起换回去**，只换 exe 不行。

## 2. 装机五步（单台，实测 10.3 秒）

### ① 把 exe 放到固定目录

```
C:\ESOP\ESOP-Client.exe
```

**不要**放在这几个地方：桌面、下载文件夹、OneDrive / 网络盘、`%TEMP%`。
前两个会被清理工具当垃圾删掉，后两个会让开机自启在断网时找不到文件。

### ② 显示器设成 1280×1024、缩放 100%

播放页是按 **1280×1024 设计画布** 做的，这个分辨率下是 1:1 像素，最清晰。
缩放设成 125% 会让整个界面按比例缩小，字变小、A7 可读性打折。

### ③ 关掉会打断播放的系统行为

| 项 | 设为 | 原因 |
|---|---|---|
| 屏幕保护 | 关 | 屏保会盖住画面 |
| 睡眠 / 休眠 | 永不 | 睡眠后不响应切换 |
| 显示超时关闭 | 永不 | 同上 |
| Windows 自动更新重启 | 设活动时间 | 半夜重启后终端会自启，但会闪一下 |

### ④ 双击 exe，走装机向导

1. 填服务器地址：`http://<服务器IP>:8092`，点 **检测**
2. 选这台屏属于哪条**线体**（如 `一线`）。只有一条线体时自动选中，不用点
3. 出现工序后，选这台屏对应的那道（如 `OP10 上料`）
4. 点 **保存并开始**

保存后自动进入全屏播放，顶栏出现 `型号 | 工序 | ● 在线` 才算成功。

### ⑤ 记下这台屏是哪道工序

5 台机器只有这一步不同。**同一道工序不要装两台**——一台屏 = 一道工序，这是本项目一期的明确取舍（没有工位概念）。

## 3. 批量部署（5 台一起）

不想在 5 台机器上各点一遍向导，就用配置外置法：

1. 在 exe 同级目录放一个 `config.json`：

```json
{
  "line": "L1",
  "op": "OP10",
  "server": "http://192.168.1.100:8092",
  "kiosk": true,
  "autoStart": true,
  "pollFallbackMs": 30000,
  "allowDevTools": false
}
```

2. 把这个 `C:\ESOP\` 整个目录拷到 5 台机器；
3. 每台只改 `op` 那一行（`OP10` / `OP20` / `OP30` / `OP40` / `OP50`）；
   `line` 是多产线时才需要区分（如一线 `L1`、二线 `L2`），留空表示"跟随服务端 sort 最前的运行中线体"；
4. 双击 exe，**不再弹向导**，直接进播放。

> 配置优先级：**exe 同级的 `config.json` > `%LOCALAPPDATA%\esop-client\config.json`（向导写的）**。
> 所以要临时改配置，改 exe 旁边那份再重启最省事。
> portable 单文件包运行时程序在临时目录里跑，`exe 同级`是靠 `PORTABLE_EXECUTABLE_DIR` 定位的，已处理（v1.3.0）。

## 4. 日常运维

### 排产与换型（工程部在管理端点一下）

管理端左栏 → **作业内容**。这一页从上到下三段：**产线概览 → 运行产线 → 操作说明**。

**① 产线概览**：一排数字，今天开线几条、几条停用 / 维修 / 保养。只数线体状态，
不掺"屏连没连上"（那是终端监控的事）。

**② 运行产线**：只列状态是「运行中」的线，一行一条：

```
一线 L1   正在生产 X210 X210 型   下一个 X220 X220 型  [换型] [✕]      在线 0/5
二线 L2   正在生产 未指定         下一个 [+ 排产下一个机种]            在线 0/5
```

| 行上有什么 | 什么意思 |
|---|---|
| 正在生产（大字标亮） | 这条线现在播哪个机种。显示「未指定」说明还没给它定机种 |
| 下一个 `+ 排产下一个机种` | 下一炉要做的。**排产只记一笔、不动终端**，可以提前一天排，关服务端也不丢 |
| `[换型]` | **点了才真正下发**。按钮变亮成橙色「换型中」，后面跟 `已就绪 2/5 · 超时强切 2:53` |
| `✕` | 取消排产 |
| `⚠ N 道工序没配` | 当前机种在这条线有工序连内容都没有，换型一定卡在那 —— 点它跳去媒体库补 |
| 在线 `0/5` | 这条线有几块屏在线 |

**操作顺序**：先点「+ 排产下一个机种」选好下一炉 → 真要换时点「换型」→ 等各屏把新内容下载齐
（按钮上能看到 `已就绪 3/5`）→ 全部就绪后一起翻。想中止点「放弃切换」。

5 台屏**先各自下载、全部就绪后才一起翻**，切换瞬间不黑屏、不混批，实测 0.9 秒内完成。
5 分钟还没齐会强制切换，没备齐的屏亮红字「内容未就绪 · 请勿作业」，旧画面继续播。
**没有屏在线时点换型会直接生效**（不用等举手）。

有屏一直不举手，点进「终端监控」看是磁盘满了还是网络卡了。

### 建工序（机种设置 → 先选机种、再选线体）

管理端左栏 → **机种设置**。这一页只回答"这个机种在这条线上有哪些工序、各是干什么的"，
**不放任何文件**：

1. 左侧选一个机种（列表上带 `5/5` 徽标，表示 5 道工序里配了几道内容）；
2. 右侧顶部是**线体选择条**：点一下选"这个机种在哪条线上配"，默认停在当前启用线体；
3. 下面是**工序清单表格**，一行一道工序：工序码 / 名称 / **做什么** / 内容数。
   25 道工序在表格里内部滚动，表头一直粘在顶上，页面高度不会越配越长；
4. 点「名称」或「做什么」直接改，**离开这一格就自动保存**（存好会绿一下）。
   「做什么」写这道工序的作业要点，会显示在终端顶栏；
5. 工序码是灰字**不能改** —— 它由「线体设置」里的工序决定，在这里改了屏就对不上号；
6. 「内容」列显示 `3 项` 或 `未配`，**点一下就跳到媒体库并定位到那道工序**。

**一次要建十几二十道**：点「+ 批量加工序」，一行一条 `OP30 压装`，从 Excel 复制两列直接粘。

**整表导入**：点「导入」，选 `.xlsx` 或 `.csv`。表里**带「机种」「线体」两列**就按行分到各自机种线体
（全厂表）；不带就导到上面选中的那个机种 + 线体（3.3.0 的老三列文件不用改）。

| 情形 | 结果 |
|---|---|
| 有标题行（"工序码 / 工序名称 / 工序内容"这类中文） | 自动跳过，不用手动删 |
| 前面多了一列「序号」、或列的顺序不对 | **按表头名认列**，不影响导入；「序号」列被忽略 |
| 表头名认不出来 | 退回按前三列位置读（工序码 / 名称 / 做什么） |
| 已有同名工序 | 三选一：**只加新的** / **加新的 + 更新有变化的** / **只更新不新建** |
| 内容跟库里一模一样 | 算「没变化」，不重写 —— 同一份表重复导对库零影响 |
| 机种 / 线体没建档、栏位空着、重码、工序码字符不合法 | 逐行标黄列原因，**这些行不导入，其它行照常进** |
| 老版 `.xls` | 提示先在 Excel 里「另存为」`.xlsx` 或 `.csv` |

> 导入是**先预览再入库**：弹窗里是一张表，每行标 `新增 / 有变化 / 没变化 / 不合要求`，
> 顶部四色计数，写清楚"读了几行、几道新增、几道会覆盖、哪几行不行"。
> 工艺表格式五花八门，行一错位就得一条条删回来，预览能省掉这一趟。
>
> **不合要求的机种/线体不会被自动建出来** —— 先把机种（机种设置 → 新建机种）和线体
> （线体设置）建好，再导一次。

**导完了**：结果窗给出新增/更新/没变化/跳过各多少；没导进去的逐行列出行号 + 工序码 + 名称 + 原因，
可点「**导出未导入明细 CSV**」存档（UTF-8 BOM，Excel 双击不乱码）。
如果这次新建了工序，还有一个「**撤销本次导入**」—— 按批次删掉这次新建的那些工序
（只删新建的；改过名的不会还原）。

**不知道按什么格式给表** → 点「模板」，下来一个五列、两行示例、另带一页填写说明的 `.xlsx`。

**想拿现有的去改** → 点「导出」，先选范围：

| 导出范围 | 用在哪 |
|---|---|
| 全厂（默认） | 一个工作表装下所有机种、所有线体。**改完能整份导回**，这是批量维护的主路径 |
| 只导出当前机种 | 拿给工艺那边单独填一个产品 |
| 只导出当前机种 + 线体 | 只想改这一块 |

> 导出的五列 `机种 / 线体 / 工序码 / 名称 / 做什么` 与导入模板**逐列同构** ——
> 拉下来、改、传回去是一条闭环。第五列以后随便加（序号、责任人、版本号），导入不读。

### 配内容（媒体库 → 先选机种、再选工位、再上传）

管理端左栏 → **媒体库**：

1. 顶部选**机种**；有两条线以上时旁边还会出现**线体胶囊条**（只有一条线时它整条隐藏）；
2. 左边「工位索引」列这条线的全部工序，点一行就编那一个；也可以点右上
   「‹ 上一个 / 下一个 ›」按顺序往下过。索引小圆点：
   **绿=有内容 / 橙=有要求但空 / 灰=连要求都没配**；顶上有 `已配/总数` 和进度条，
   还有「全部 / 有内容 / 空」三个筛选和搜索框；
3. 卡上先勾**允许类型**：图片 / 视频 / PDF。**不勾的类型传不上去**（服务端直接拒）；
4. 把文件拖到卡里，传完自动变成内容项，可以排序、设停留秒数、设图片显示方式；
5. 点「保存」——这张卡的要求和内容一起提交，要么全成、要么全不动。

> 「允许类型」放在媒体库而不是机种设置，是因为**它只在上传那一刻起作用**：
> 传文件的时候就在眼前，不用回另一页去勾。

> 一个机种常有 15–25 道工序，所以**一次只显示一个工位**：页面高度是固定的，
> 不用在四五千像素的长条里找"哪个还没配"。配完一个点「下一个」接着配就行。

> **内容挂「机种 × 线体」**。同一个机种在一线和二线都做，**两条线各配一套**，
> 因为两条线的工序划分本来就不一样（编码都不同）。一线改 OP30 不会动到二线 OP30。

**新线上第一次配置，不用从零录**：点右上「从其它线复制…」，选源线体、勾要复制的工序，
可选"覆盖已有内容"，确定即可。

| 目标工位 | 结果 |
|---|---|
| 空的 | **直接填上**（大多数情况） |
| 已有内容 | **默认跳过**，勾了"覆盖"才替换 |

所以重复点复制不会叠加、也不会把现场已经调好的内容冲掉。

工序与线体的对应靠**工序码，但只在同一条线内对位**：这条线有 OP30，本线机种的工序里就要有 OP30。
线体设置里加了新工序后，回「**机种设置**」点「**按本线工序补齐**」——**只补不删**，
机种里多出来的工序不会被清掉。

### 找文件 / 体检 / 清理（文件查询）

左栏 → **文件查询**。这里管的是**全库文件**，不管它挂在哪个机种上：

| 想干什么 | 怎么做 |
|---|---|
| 找某个文件在哪 | 顶上按文件名搜；也可以只看图片 / 视频 / PDF |
| 看哪些文件规格不合适 | 点「规格体检」 |
| 回收没人用的文件 | 点「清理未引用」（会先列出来让你确认） |

> 这里也能直接「上传文件」，但传上去的文件**还没有归属**，要回媒体库在具体工序里引用它。
> 日常传图请在媒体库传，一步到位。

### 换线 / 停线 / 维修（今天跑哪条线）

左栏 → **线体设置**，一张表格列出所有线体：

| 列 | 说明 |
|---|---|
| 状态（下拉） | **运行中** = 这条线今天在跑，终端读它的内容；停用 / 维修中 / 保养中 = 都不读 |
| 编码 / 名称 | 编码是终端装机时要填的标识，一般不改 |
| 工序数 / 内容覆盖 | 这条线有几块屏、当前机种配齐了几个工位 |
| 当前机种 / 在线 | 这条线正在播什么、有几台屏在线 |
| 操作 | 查看、改名、上下排序、删除 |

**多条线可以同时是「运行中」**（v3.5.0 起）—— 现场每条线有自己的终端，各带 `?line=L1`，
互不干扰。只有一种情况仍按"一条"处理：**不带 `line` 参数的老终端**会跟 sort 最前的那条。

从「运行中」改成另外三种会先弹确认框：那条线的终端会连不上、屏上内容停在最后一屏
（不会变空白），别的线不受影响。改回「运行中」随时可以。

线体表下面是**工序表**（这条线有几块屏、各叫什么）。改工序名会显示在终端顶栏；
加一道工序 = 这条线多一块屏，各机种会自动补出对应工位。
**一次要加十几二十道**就用「批量加工序」：一行一条 `OP30 压装`，从 Excel 复制两列直接粘，`Ctrl+Enter` 提交；
加完各机种那边也会一次性多出这些工位（不够再点「按本线工序补齐」）；
删工序不再因为"有内容"被拦住——内容是「机种 × 本线」的，删掉工序等于这条线撤掉那块屏，
本线的工位与内容暂时看不到，但**没有真删**，把同一道工序按原名加回来就还在。

> **改工序编码要小心**：v3.0.0 起改码会**带着本线工位一起改**，内容不会丢。
> 但屏上那台终端存的还是老码，改完它取不到内容，得去终端「更改设置…」把工序改成新码。
> 所以现场运行中不要随手改码，最好趁换型停机时改。

### 看终端状态（「终端监控」页）

左栏 → **终端监控**，每台屏一行，字段横排不截断：

| 字段 | 含义 |
|---|---|
| IP 地址 / 分辨率 / 版本 | 终端上报的本机参数 |
| 剩余磁盘 | 终端磁盘剩余空间，低于 1 GB 要留意 |
| 下载进度条 + `X300 3/12 项` | 这套内容下到第几项；转绿 + 「已就绪」表示已举手可翻 |
| 状态 | 在线/下载中、在线已就绪、已离线 N 分钟、从未上线 |

「作业内容」页只看"有没有线在跑、换型点到哪一步"（在线数是几个数字），
逐台屏的明细在这里看；换型前扫一眼就够；
要查 IP、分辨率、磁盘这些细节就切到这张表。

- 「从未上线」= 这台屏从来没连过服务器，先查是否装了、IP 通不通。
- 「已离线 N 分钟」= 连过，现在断了（关机/网线掉了）。
- 参数显示「—」= 那台终端的版本还低于 1.6.0，升级后就能看到。

### 改内容（改错图、补注意事项）

管在理端改完清单**保存即可**，终端会在 0.3 秒内自动重下并刷新——**不需要换型，也不需要重启终端**。
（v1.3.0 新增：服务端 `contentRev` + 终端清单指纹比对。改的是别的工序时，本机不会闪屏。）

### 托盘

右下角托盘图标右键：

| 菜单 | 用途 |
|---|---|
| 重新加载画面 | 画面异常时先点这个 |
| 重新同步内容 | 怀疑内容不对时点 |
| 打开内容目录 | 看本地缓存了什么 |
| 打开日志 | 排障第一现场 |
| 更改设置… | 改服务器地址 / 工序 |
| 退出 | 正常退出（生产上一般不用） |

### 退出与逃生

- 窗口关不掉（kiosk + 关窗拦截）是设计如此；
- **`Ctrl + Alt + Shift + Q`** 强制退出，这是唯一的逃生门，请写在工位交接卡上；
- `Alt+F4` / `Ctrl+W` / `F11` / `F5` 全部被拦截。

### 开机自启

保存配置后自动写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
（项名 `com.frank.esop-client`，值为 exe 路径 + `--autostart`）。
换机器、换目录后要重新保存一次配置，否则注册表里还是旧路径。

## 6. 故障排查

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| 双击没反应 | 已经在跑（单实例锁） | 看托盘；或 `Ctrl+Alt+Shift+Q` 退掉再启动 |
| 顶栏红底白字「内容未就绪 · 请勿作业」 | 本机没下完内容，服务端已经超时强翻 | 别动，等它自己补齐；一直不变看日志确认网络 |
| 顶栏灰点「离线」 | 连不上服务器 | `ping 服务器IP`、确认 8092 端口、确认服务端在跑 |
| 橙字「内容不全 0 项」 | 这个型号这道工序没配内容 | 管理端补内容，保存后自动生效 |
| 画面比例不对 / 两边黑边 | 这不是故障 | 指导书不是 16:9 时会留黑边，**刻意不裁图** |
| 字太小看不清 | 显示器缩放不是 100% | 改回 100%，见第 2 节 ② |
| 一直卡在「准备中」 | 网络太慢或超大视频 | 看日志下载进度；5 分钟未完成会转红字告警 |
| 开机没自启 | 移动过 exe 或换了目录 | 托盘 → 更改设置 → 再保存一次 |

## 8. 指导书制作规范（给工程部）

现场 19 寸屏、1 米观看距离，光学上 2 mm 特征有 6.9 倍余量，但**这几个约束决定余量会不会被吃掉**：

| 项 | 要求 | 原因 |
|---|---|---|
| 画幅 | **1280 × 720（16:9）** | 内容区是 1280×816，16:9 图正好 1280×720，**1:1 零缩放** |
| 不要用 1920×1080 | 会被压到 0.667x | 2 mm 细节只剩 4.5 个像素采样，等于白做高清 |
| 不要用 4:3（如 1280×1024） | 会被压到 1020×816 | 2 mm 特征缩水到 5.4 px |
| 视频 | 1280×720，H.264，≤3 Mbps | 5 台并发下载要在 5 分钟内完成（单套建议 ≤120MB） |
| 关键细节 | 不小于 7 px（≈2 mm） | 这是 A7 的判据线 |
| 字体 | 正文 ≥24 px | 48 px 约等于 1 cm 高的字，1 m 外很轻松 |

> 一句话：**按 1280×720 出图，别往上传 1080P 甚至 4K**，上传大图不会更清楚，只会更慢。

**v1.6.0 起的两点变化**（内容制作时注意）：

1. **PDF 可以直接传**。服务端会按页渲染成 PNG（A4 竖版输出 1086×1536，约 26 KB/页），
   一页一条记录，按顺序进播放队列。适合直接丢工程部现有的 PDF 指导书，不必手工截图。
   上限 200 页/份；加密 PDF 会报错。要挑页请先在源文件里删好再传。
2. **图片显示方式每项可调**（清单里选）：`适应·不裁`（默认）/ `铺满·裁边` / `缩放 50%–200%`。
   如果 16:9 素材投到 5:4 屏上觉得黑边太大，可以选"铺满"，但**会裁掉两边内容**，
   指导书上的尺寸标注别贴着边缘放。视频时长不再限 60 秒，
   界面会按实际字节数算"预计换型耗时"给你看。

## 9. 已知限制（一期明确不做）

- 没有工位/终端档案管理：一台屏 = 一道工序，只配 `op`
- 不能分屏各自设型号：换型全网统一
- 不保留历史型号内容：切完即删，想回看要重新下载
- 没有权限和操作审计：谁都能换型（记录只在日志里）
- 清单一改就整批重下（约 27 MB），不是增量
- exe 未做代码签名：Windows 首次运行可能提示"未知发布者"，选"仍要运行"即可
