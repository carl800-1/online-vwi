## 1. 验收环境

| 项 | 实际值 |
|---|---|
| 机器 | Windows 11 Pro（10.0.26200），14 核 / 31.5 GB |
| 显示 | 1536 × 864 @ 1.25 缩放（**不是** 19 寸 1280×1024 工位屏） |
| 服务端 | Node 22.22.2 + `node:sqlite`，端口 8092 |
| 终端 | Electron 31.7.7，同一台机器上并发 4 个实例（OP10 / OP20 / OP30 / OP40 / OP50） |
| 终端隔离 | 每个实例独立数据根（`VWI_TERMINAL_ROOT`），互不干扰 |
| 网络 | 本机回环 + 一个限速代理（10 KB/s，用于复现弱网掉队） |

> 为什么用一台机器开 4 个实例：A1 要验的是"5 台同一瞬间翻"，同一台机器上并发多实例
> 对时序的要求比跨机器更严格（共用 CPU 和磁盘），过了这一关，跨机器只会更松。
> **但它替代不了真机**：网卡、Wi-Fi、屏幕尺寸的差异只能在现场验，见第 6 节。

### A10 的细节（这条最容易做成"看起来对"）

时间线（服务端超时设为 30 秒以便验证，正式仍是 5 分钟）：

```

t=28.6s  OP20 准备中 0/3，旧图继续循环          OP10 准备中 3/3
t=30.1s  OP20 内容未就绪 · 请勿作业（红字）      OP10 在线，已换 X230
```

## 5. 这次验收发现并修掉的 3 个缺陷

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | **终端在 prepare 阶段 `await` 下载完成，把主循环堵死** | 弱网那台永远收不到"服务器已强翻"的通知，只会一直显示"准备中"，**A10 的故障被藏起来**——这是本次最严重的一个 | 下载改后台跑，循环继续轮询；下载完成且服务端已翻则立即自愈补播 |
| 2 | `userData` 在抢单实例锁之后才设置 | 缓存/库落在默认 `%APPDATA%\Electron`；测试时多实例互相抢锁、第二台直接退出 | 把 `setPath('userData')` 提前到 `requestSingleInstanceLock()` 之前 |
| 3 | `installLogger()` 被调用两次，`console` 被包两层 | 日志每行重复一遍，排查时容易误判"怎么执行了两次" | 加幂等标志 |

另有一处**非缺陷的改动**：切换总超时改为可用 `VWI_SWITCH_TIMEOUT_MS` 覆盖（默认仍是 5 分钟）。
不加这个，每验一次掉队告警都要干等五分钟。

### 9.4 A7 几何与光学（实测数据，不是推算）

在真实播放页里把视口模拟成 19 寸面板的 1280×1024，量出来的实际布局：

| 项 | 实测 |
|---|---|
| 顶栏 / 底栏 | 88 px / 120 px（固定，不吃分辨率） |
| 内容区 | **1280 × 816** |
| 1280×720 检验卡 | 实画 **1280 × 720，缩放比 1.000x，零重采样** |
| 1920×1080 指导图 | 实画 1280×720，缩放 0.667x（2 mm 细节只剩 4.5 个源像素） |
| 19″ 5:4 面板像素间距 | 0.2944 mm/px（可视区 376.8 × 301.5 mm） |
| 2 mm 特征 | **6.8 屏像素**，1 m 处张角 **6.9 弧分** |
| 人眼分辨极限 | 1 弧分 ⇒ **余量 6.9 倍** |

**结论**：判据在光学上成立，且余量很大。但 1920×1080 源图会被压到 0.667x，
等于把余量白白还回去 —— 所以指导书一律按 **1280×720** 出图（见部署手册第 8 节）。

现场只需做一件事：把 `docs/a7-检验卡-1280x720.png` 投上屏，站到 1 米，
看 2.0 mm 那五行竖线是否根根分明；同时用卡尺量卡上的黑条，应是 10.0 mm。

### 9.5 M4 期间发现并修掉的问题

| 问题 | 影响 | 处理 |
|---|---|---|
| **同型号下改清单，终端不刷新**（服务端只 bump `rev`，从没告诉终端"内容变了"） | 工程部改错图后，屏上还是老图，且**换型才更新**——生产上会照着错图作业 | 服务端新增 `contentRev`；终端比对清单指纹，变了才重载，没变只记版本号（不闪屏） |

| 播放页 `fit()` 只在启动时算一次（后面靠 2 秒轮询兜） | 改分辨率后最多 2 秒内画面比例不对 | 保留轮询（已验证能自愈），无需改代码 |

### 10.3 编码踩坑（这部分比功能更值得记）

cmd.exe 读 `.bat` 是**用当前 OEM 代码页把整个文件一次性解码**，`chcp` 之后再改不会重新解码已读内容。三种存法实测：

| 存法 | 实测现象 |
|---|---|
| UTF-8 无 BOM | cmd 按 936 解读，中文变乱码字节，其中的 `0x5C` 被当成反斜杠 → **命令被拆坏**：`'TENING" >nul 2>&1' 不是内部或外部命令` |
| UTF-8 + BOM | cmd **不认** BOM，当成命令的一部分：`'﻿@echo' 不是内部或外部命令`，且 `@echo off` 失效、后面所有命令回显 |
| GBK | 中文 Windows（936）上完全正确，命令结构不被破坏 ✅ |

再加上 **node 的 stdout 永远是 UTF-8 字节**（实测 936 控制台里 node 横幅是双重编码乱码），
最终形态定为 **GBK 存文件 + 分段 chcp**：

```
chcp 936   → bat 自己的中文提示（GBK 字节，936 控制台正确显示）
chcp 65001 → node 横幅（UTF-8 字节，6501 控制台正确显示）
chcp 936   → node 结束后的收尾提示
```

验证方式：把 cmd 的输出重定向到文件后按 CP936 解码，逐字核对（不是肉眼看截图）。
另附一套**纯 ASCII 英文脚本**（`start-server.bat` 等）供英文版 Windows 使用 —— 纯 ASCII 在任何代码页下都不会被拆坏。

## 11. v1.5.0：服务端桌面程序（不用浏览器的图形界面）

需求原话：「服务端要有程序界面，不用这种网页访问的」。选了 Electron 桌面壳 + 关窗口缩托盘常驻。

### 11.2 为什么必须换 Electron 大版本（这是本次最硬的约束）

服务端数据层用 `node:sqlite`。终端端一直用的 **Electron 31 内置 Node 20.18，实测没有这个模块**
（`No such built-in module: node:sqlite`）。Electron 40 内置 Node 24.15，同一段代码直接跑通，
无需 flag。两套 Electron 各自独立（终端 31.7.7 / 服务端 40.10.3），互不影响。

### 11.4 两个必须记住的坑

**① Electron 的 app 参数必须用绝对路径。**
传 `.` 时 `require('electron')` 返回的是**字符串**（npm 包 `electron/index.js` 导出的是 exe 路径），
于是 `app` / `BrowserWindow` / `ipcMain` 全是 undefined，而报错完全不指向原因。
试过的无效办法：`process.getBuiltinModule('electron')`（undefined）、`electron/main`（模块不存在）、
ESM 具名导入（`does not provide an export named 'BrowserWindow'`）、ESM default 导入（空对象）。
项目里 `terminal/tools/run-term.cjs` 一直用绝对路径，所以终端端从没踩到这个坑。
> 判断法：只要 `require('electron')` 拿到的对象没有 `app`，先查 app 参数是不是相对路径。

**② ESM 主进程拿不到 electron API。**
最终写法是 `createRequire(import.meta.url)` 拿到 CJS 的 require（活对象，没有快照问题），
并且**只提前取 `app`**，其余成员在 `app.whenReady()` 之后再解构 —— 因为 `BrowserWindow`、`ipcMain`、
`Tray`、`dialog` 这些在 app ready 之前根本没挂到导出对象上。

打包参数 `asar: false`（服务端的 ESM 模块放在 asar 内加载行为不稳，且总共只有 21 个文件，
加密收益为零）。electron-builder 会警告 "asar usage is disabled"，属预期。

### 11.5 顺手修掉的两个缺陷

- `/api/status` 的 `version` 硬编码为 `'2.0.0'`（一个根本不存在的版本）。新增 `src/version.js`
  统一读 `package.json`，现在横幅、接口、EXE 文件名三处一致。
- 日志缺 UTF-8 BOM，中文 Windows 记事本默认按 ANSI 解码会整篇乱码。而现场排障第一步
  就是双击 `server.log`，这属于"小到不写、但真会卡住人"的坑。
