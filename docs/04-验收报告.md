# 验收报告 · 在线VWI发布系统 v1.2.0

> 本报告记录的是**在真实 Electron 窗口里跑出来的结果**，不是"代码看起来对"。
> 每一条结论都有对应的截图、日志或逐帧采样数据，放在 `terminal/tools/probe/probe-out/`。
>
> 结论先说：**A1 / A2 / A5 / A8 / A9 / A10 通过；A3 通过（45 秒实测，8 小时待夜间跑）；
> A4 / A6 / A7 需要在 19 寸工位屏和现场无线环境上补测。**

---

## 1. 验收环境

| 项 | 实际值 |
|---|---|
| 机器 | Windows 11 Pro（10.0.26200），14 核 / 31.5 GB |
| 显示 | 1536 × 864 @ 1.25 缩放（**不是** 19 寸 1280×1024 工位屏） |
| 服务端 | Node 22.22.2 + `node:sqlite`，端口 8092 |
| 终端 | Electron 31.7.7，同一台机器上并发 4 个实例（OP10 / OP20 / OP30 / OP40 / OP50） |
| 终端隔离 | 每个实例独立数据根（`VWI_TERMINAL_ROOT`），互不干扰 |
| 网络 | 本机回环 + 一个限速代理（10 KB/s，用于复现弱网掉队） |

> 为什么用一台机器开 4 个实例：A1 要验的是"5 台同一瞬间翻"，同一台机器上并发多实例
> 对时序的要求比跨机器更严格（共用 CPU 和磁盘），过了这一关，跨机器只会更松。
> **但它替代不了真机**：网卡、Wi-Fi、屏幕尺寸的差异只能在现场验，见第 6 节。

## 2. 怎么测的

| 手段 | 用途 |
|---|---|
| **CDP 逐帧采样**（每 70 ms 读一次 DOM） | 判断"这一屏此刻到底显示哪张图"。只看 `.layer.on` 那一层——隐藏层里的新内容人是看不见的 |
| **窗口截图**（`Page.captureScreenshot`） | 留证。每张都是终端真实像素，不是页面 mock |
| **服务端接口 + 数据库** | 交叉核对型号、seq、ready、在线工序 |
| **终端日志** | 主进程时间线（托盘、自启、快捷键、就绪、举手、掉队） |
| **注册表读取** | 验证开机自启真的写进去了 |
| **限速代理** | 把 10 MB/s 的下载压到 10 KB/s，人为制造"掉队那台" |

| **A6** | 全新机器从开机到播出 ≤5 分钟 | 未测（需一台没配过的机器；装机向导与探服务器逻辑已就绪） | ⏳ 待现场 |

| **A8** | 切换后旧文件确实删除，只剩 1 套 | 4.9 MB 三文件切回小图后：**文件数 1、目录 21 KB、旧型号文件 0 个**；连切 3 轮文件数与体积恒定 | ✅ 通过 |
| **A9** | 单屏内不存在半新半旧 | 全程采样中"两层同时可见" **0 次**；"顶栏与画面不一致" **0 次** | ✅ 通过 |
| **A10** | 掉队那台会被看见 | 限速终端在 30 秒超时后：顶栏变**红底白字「内容未就绪 · 请勿作业」**，画面继续播旧型号不黑屏；服务端 ready 列表缺该工序 | ✅ 通过 |

### A10 的细节（这条最容易做成"看起来对"）

时间线（服务端超时设为 30 秒以便验证，正式仍是 5 分钟）：

```
 t=0.0s  OP20 准备中 0/3，继续播 X220 旧图      OP10 准备中 3/3（已举手，等全员）
t=28.6s  OP20 准备中 0/3，旧图继续循环          OP10 准备中 3/3
t=30.1s  OP20 内容未就绪 · 请勿作业（红字）      OP10 在线，已换 X230
t=44.7s  OP20 仍红字，旧图继续循环              OP10 正常播新内容
```

关键点：**掉队那台没有因为"等不及"变成黑屏或空白**，它保住旧画面并亮红字，
这正好符合"宁可让人看见不能让人猜"的原则。

## 5. 这次验收发现并修掉的 3 个缺陷

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | **终端在 prepare 阶段 `await` 下载完成，把主循环堵死** | 弱网那台永远收不到"服务器已强翻"的通知，只会一直显示"准备中"，**A10 的故障被藏起来**——这是本次最严重的一个 | 下载改后台跑，循环继续轮询；下载完成且服务端已翻则立即自愈补播 |
| 2 | `userData` 在抢单实例锁之后才设置 | 缓存/库落在默认 `%APPDATA%\Electron`；测试时多实例互相抢锁、第二台直接退出 | 把 `setPath('userData')` 提前到 `requestSingleInstanceLock()` 之前 |
| 3 | `installLogger()` 被调用两次，`console` 被包两层 | 日志每行重复一遍，排查时容易误判"怎么执行了两次" | 加幂等标志 |

另有一处**非缺陷的改动**：切换总超时改为可用 `VWI_SWITCH_TIMEOUT_MS` 覆盖（默认仍是 5 分钟）。
不加这个，每验一次掉队告警都要干等五分钟。

## 6. 未覆盖 / 必须到现场补的

| 项 | 为什么本机测不了 | 现场怎么测 |
|---|---|---|
| A7 看清 2 mm | 本机是 1536×864 显示器，不是 19 寸 1280×1024 | 拿一张真实指导书投上去，1 米处比对 2 mm 特征 |
| A4 断网 8 小时 | 要过夜 | 下班断 AP，第二天看画面与日志 |
| A6 全新机器装机 | 需要一台没配过的机器 | 迷你主机开机 → 填服务器地址 + 选工序 → 掐表 |
| 无线真实带宽 | 回环无限速（除了人为代理） | 5 台同时在 AP 下切一次，看总耗时 |
| 托盘菜单交互 | 需要人手点 | 点"打开日志""重新同步内容"各一次 |
| 27 MB 真实体量 | 测试图 1.6 MB/张（用噪声图撑体积） | 换成真指导书，验证 A8 的目录体量 |

## 7. 怎么复跑

```bash
# 服务端（可选短超时，方便验掉队）
VWI_SWITCH_TIMEOUT_MS=30000 node server.js

# 三台终端（不同工序、不同调试端口）
cd terminal
node tools/run-term.cjs t1 --op=OP10 --server=http://127.0.0.1:8092 --kiosk=false --dev --remote-debugging-port=9223 --no-sandbox
node tools/run-term.cjs t2 --op=OP30 --server=http://127.0.0.1:8092 --kiosk=false --dev --remote-debugging-port=9224 --no-sandbox
node tools/run-term.cjs t3 --op=OP50 --server=http://127.0.0.1:8092 --kiosk=false --dev --remote-debugging-port=9225 --no-sandbox

# 造测试内容（大图 + 小图）
node tools/gen-media.cjs X210
node tools/seed-model.mjs X210 http://127.0.0.1:8092
node tools/gen-media.cjs X220 --noise=2 --count=3
node tools/seed-model.mjs X220 http://127.0.0.1:8092

# 同步切换验收（A1 / A2 / A9）
node tools/acceptance.mjs switch X210 9223:OP10 9224:OP30 9225:OP50

# 断电恢复（A5）
node tools/wait-ready.mjs 9223 <启动时刻文件>

# 断网续播（A3）
node tools/offline-test.mjs 45 9223:OP10 9224:OP30 9225:OP50

# 掉队告警（A10）：起限速代理，让一台走代理
node tools/slow-proxy.mjs 8095 http://127.0.0.1:8092 10240
node tools/run-term.cjs t4 --op=OP20 --server=http://127.0.0.1:8095 --kiosk=false --dev --remote-debugging-port=9226 --no-sandbox
curl -X POST http://127.0.0.1:8095/_slow/on
curl -X POST http://127.0.0.1:8092/api/switch -H "content-type: application/json" -d '{"modelCode":"X230"}'
node tools/offline-test.mjs 45 9226:OP20 9223:OP10

# 快捷键拦截与逃生门
node tools/key-test.mjs 9228 alt+f4
node tools/key-test.mjs 9228 ctrl+alt+shift+q
```
