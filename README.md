# 在线 VWI 发布系统

产线**可视化作业指导书（VWI）**的在线发布与换型系统。

一台 PC 作服务器，每道工序一块屏。工程部在服务器上按「型号 × 工序」配好播放清单，
**班长改型号，全线屏同时换成新型号的指导书**——不用换纸、不用换 U 盘、不用挨个工位跑。

> 独立自研项目。不基于任何第三方产品的代码，内容模型与切换协议均为本项目设计。

---

## 一、内容模型：只到工序为止

```
型号 Model ──┬── 工序 OP10 ── 播放清单（图 / 视频，有序，循环播）
             ├── 工序 OP20 ── 播放清单
             ├── 工序 OP30 ── 播放清单
             ├── 工序 OP40 ── 播放清单
             └── 工序 OP50 ── 播放清单
```

**没有工位这一层**，这是刻意的设计：一台屏 = 一道工序，屏上只配一个工序号 `op`，
这个 `op` 就是它的全部身份。没有工位档案、没有终端注册、没有逐台设置。

带来三个直接后果：

| 好处 | 原因 |
|---|---|
| 换型是**全线统一**的 | 只有"现在做哪个型号"一个状态，不存在某台屏跑别的型号 |
| 装机是**零配置**的 | 打开 `player.html?op=OP30` 就行，剩下全靠服务器推 |
| 数据表只有 **5 张** | 没有工位表、没有终端表、没有发布单表 |

## 二、换型机制（本项目最关键的部分）

### 两段式：先备齐，再一起翻

工位屏网速不一样。如果各下各的、下完各自翻，快的 3 秒翻、慢的 40 秒翻，
中间这半分钟里前道已按新型号作业、后道还看着旧型号 —— **直接混批**。

所以切换分成两段：

```
① 班长点"切换到 X400"
   └─ 服务器 phase=prepare，广播目标型号（此时画面不动，继续播旧内容）
   └─ 各终端后台下载并校验本工序内容，顶栏显示"准备中 3/11"
   └─ 下完 → POST /api/ready 举手
② 所有在线终端都举手
   └─ 服务器 phase=activate，seq+1
   └─ 各终端同一瞬间整屏翻，翻完立即释放旧内容
```

**铁律：要么整批全翻，要么一台都不翻。** 不存在"一屏里混两个型号"的中间态。

### 5 分钟到点也翻

一台屏网络烂不能拖整个产线停产，所以超时（默认 5 分钟）**强制激活**：
备好的翻，没备好的保持旧画面并顶栏红字 `内容未就绪 · 请勿作业`，
管理端能指出是哪道工序没跟上（验收项 A10）。

### 本地只留一套，旧内容切完即删

终端磁盘上任何时候只有**当前这一套**（约 27MB），翻页成功后旧内容立即释放。
不做历史型号归档、不做"回滚到上一型号"的本地快照。好处是终端永远不会拿错型号播。

### 为什么不用 WebSocket

长轮询在原生 `http` 上就能写，零依赖。25 秒挂起 ≈ 一次普通请求，无线抖动时重连成本极低；
断线后 30 秒兜底轮询，网络恢复自动接上，不需要任何重连状态机。

## 三、快速开始

要求 **Node.js ≥ 22.5**（用内置 `node:sqlite`，**零 npm 依赖**，不用 `npm install`）。

```bash
node server.js                  # 默认 8092 端口
node server.js --port=8092      # 指定端口
```

首次启动自动建库并写入种子数据：**10 个型号（X200–X290）× 5 道工序（OP10–OP50）**，
内容全空，完成度从 `0 / 50` 开始。数据落在 `data/`（已 gitignore，含 `vwi.db` 与媒体文件）。

启动后控制台会打印局域网地址，终端装机时直接填：

```
  管理端    http://127.0.0.1:8092/
  终端画面  http://127.0.0.1:8092/player.html?op=OP30
  局域网访问（终端装机器上填这个）：
    http://192.168.1.4:8092
```

### 三个页面

| 页面 | 地址 | 谁用 |
|---|---|---|
| 管理端 | `/` | 工程部配内容、班长换型 |
| 终端画面 | `/player.html?op=OP30` | 工位屏全屏打开 |
| 媒体库 | `/` → 媒体库标签 | 查文件、清理未引用 |

### 日常操作

1. **配内容**：管理端矩阵里点某个格子（如 `X200 / OP30`）→ 拖入图片或视频 → 排序、设停留秒数 → 保存
2. **换型**：顶栏选型号 → 点「切换」→ 等各屏举手 → 全线同时翻
3. **改工序名**：点表头的工序名（如 `OP10 上料 ✎`），改完会显示在终端顶栏

## 四、接口（13 个）

```
GET    /api/models                型号列表（含每个型号的完成度、每格内容项数）
POST   /api/models                新增型号
PUT    /api/models/:id            改型号（编码 / 名称 / 停用）
GET    /api/processes             工序列表
PUT    /api/processes/:id         改工序名称

GET    /api/playlist?modelId=&processId=     读某格清单
PUT    /api/playlist              整批覆盖保存（校验失败则一条不动）

POST   /api/media/upload?filename=           原始流上传，自动 sha256 去重
GET    /api/media                 媒体列表（含被引用次数）
POST   /api/media/gc              回收未引用媒体（默认 dryRun）
GET    /api/media/advice          规格体检（非 5:4、图片过大）

POST   /api/switch                {modelCode} 发起换型
POST   /api/switch/cancel         放弃本次换型（画面保持原型号）
POST   /api/ready                 {op, modelId} 终端举手：本工序已备齐
GET    /api/state?op=&since=      长轮询（25 秒），返回 phase/seq/current/pending/online/ready

GET    /display/boot?op=          终端启动自检：我是谁、现在该播什么
GET    /display/playlist?op=&model=  终端拉清单（当前槽刷新与预备下载共用）
GET    /m/:id                     媒体流，支持 Range（视频拖动、断点续传）
```

**一期无鉴权**（用户明确「先不考虑权限管理」）。`op` 不是权限，而是"我是哪道工序"这个身份。
代价是内网任何人都能拉到内容，所以有一条硬约束：**服务端只能跑在车间内网，不得映射到公网。**

## 五、数据表（5 张）

| 表 | 作用 |
|---|---|
| `model` | 产品型号 |
| `process` | 工序（固定 5 条，名称可改） |
| `media` | 媒体，sha256 内容寻址，多型号共用同一张图只存一份 |
| `item` | 播放清单项：`(型号, 工序)` 下的一条，带排序与停留时长 |
| `setting` | 全局 KV：`current_model_id` / `seq` / `pending_model_id` / `pending_deadline` / `rev` |

**刻意不建**：`station`（已取消这一层）、`user` / `session`（不做权限）、`release`（不做版本治理）、
`play_log`（不做统计报表）、`page` / `block`（不做版式）、`switch_log`（切换写进程日志即可）。

两个计数器分工要分清：
- `seq` —— 业务语义，**只在激活时 +1**，终端据此判断"该翻页了"
- `rev` —— 通信语义，任何需要通知终端的变化都 +1（进 prepare、激活、清单被改）

## 七、测试

```bash
node test/run.mjs        # 或 npm test
```

会起一个**临时数据目录**的实例（端口 8093），跑完自动关掉并删除数据——不会弄乱开发数据。

覆盖 47 项断言，重点在切换协议：

| 组 | 验的是什么 |
|---|---|
| 档案 | 10 型号 × 5 工序、完成度分母 50 |
| 上传清单 | 同文件去重、宽高解析、重复项拒绝、**失败保存不破坏原清单** |
| 无终端在线 | 直接激活（否则管理端永远卡在"准备中"） |
| 两段式 | prepare 不动 seq、1/2 台备好**不激活**、集齐才翻、seq 只 +1 |
| 工序隔离 | 同型号不同工序内容互不影响、空内容显式返回 `empty` |
| 过期举手 | 拿旧型号举手返回 409 |
| 放弃切换 | 回到 idle、当前型号不变、不消耗 seq |
| 媒体流 | MIME、Range 206、404 |

## 九、已知限制

| 限制 | 说明 / 何时需要处理 |
|---|---|
| 终端是浏览器页，不是 exe | 浏览器拿不到磁盘槽和自启能力。正式部署走 M3 打包；协议已经按 exe 的磁盘槽设计 |
| 浏览器端不校验 sha256 | 非 HTTPS 下 `crypto.subtle` 不可用。exe 端必须校验 |
| 清单改动会整批重下 | 改一张图也重下整套（约 27MB）。内容量大了再做增量 |
| 型号数量按 10 个设计 | 加型号不受限，但矩阵会变长，届时按启用状态过滤 |
| 无权限、无操作日志 | 一期的明确取舍，切型记录只写进程日志 |

## 十、明确不做

- ❌ 工位 / 终端档案管理（一台屏 = 一道工序，只配 `op`）
- ❌ 分屏独立设型号（换型全网统一）
- ❌ 本地历史型号归档（旧内容切完即删）
- ❌ 边下边播 / 分批生效（必须备齐后整批翻）
- ❌ 视频转码（格式由工程部按规范产出：720p / H.264 / 单段 60 秒内）
- ❌ 多区域分屏、触摸交互、扫码换型
- ❌ 公网部署、加密狗
