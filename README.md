# ESOP 发布系统

产线**可视化作业指导书（VWI）**的在线发布与换型系统。

一台 PC 作服务器，每道工序一块屏。工程部在服务器上按「机种 × 工序」配好播放清单，
**班长在总览页选机种、点换型，全线屏同时换成新机种的指导书**——不用换纸、不用换 U 盘、不用挨个工位跑。

> 独立自研项目。不基于任何第三方产品的代码，内容模型与切换协议均为本项目设计。

---

## 一、内容模型：机种 × 工序

```
线体 一线（运行中 · 5 块屏）── 可生产 ─┐
线体 二线（停线）           ── 可生产 ─┤
                                       ↓
机种 X200 ─┬── OP1 装配 ── 播放清单（图 / 视频 / PDF 页，有序，循环播）
           ├── OP2 调试 ── 播放清单
           └── OP3 检验 ── 播放清单
```

两层各管一件事：

| 层 | 管什么 | 数据表 |
|---|---|---|
| 机种 | 产品（编码、名称）+ **它有几道工序、每道看什么** | `model` / `model_line` / `process` / `process_req` / `item` |
| 线体 | 这条线**有几块屏**、状态（运行/停线/维修/保养）、**能做哪几个机种** | `line` / `line_state` |

**工艺跟着产品走，内容按机种各存一份。** 同一个机种在一线和二线做，装配还是装配、检验还是检验，
两条线播的就是同一套内容 —— 这也是「可生产机种」能自动统计的前提：机种勾了哪几条线，
线体那页就算出几。

4.0.0 之前这里夹着**「工位」**：机种 × 线体 × 工位三元组。两道工序的机种放到两条线上要维护
4 个工位，全是空壳；改一道工序要改所有线的同码工位，漏一条就一边新一边旧。现在这一层并回了工序。

带来三个直接后果：

| 后果 | 原因 |
|---|---|
| 换型是**单线统一**的 | 每条线只有一个"现在做哪个机种"，一条线换型不影响另一条 |
| 加工序**只加工种** | 这个机种多一道工序，所有能生产它的线一起生效 |
| 删机种**连内容一起删** | 工序和内容都是机种专属的，机种没了没人读 |

**没有工位档案、没有终端注册、没有逐台设置**——屏的身份只有「机种 + 工序码」，
所以现场加一块屏就是把它接上、在 `config.json` 里填 `line` 和 `op`。

---

### 工序要求：规定"这道工序允许放什么"

```
机种 X200
  └ 工序 OP1 装配
      ├ 允许类型 ── 图片 / 视频 / PDF（有行 = 允许，min_count = 至少几份）
      ├ 单文件体积上限
      ├ 播放方式 ── 循环播放 / 播一遍停
      └ 内容清单 ── 按顺序播，可设停留秒数
```

- 某个 kind **有行** → 允许放这类文件，`min_count` 是"至少几份"
- 某个 kind **没行** → 这道工序不接受这类文件，上传直接被服务端拒（`400 这道工序不允许放视频：…`）
- reqs **整张为空** → 视为未配置，**不做类型锁**（迁移后不必先勾一遍才能用）

保存是**整批覆盖**：内容与要求一次 `PUT` 提交，前端先整批校验，后端事务内先删后插，不留半套。

## 二、换型机制（本项目最关键的部分）

### 两段式：先备齐，再一起翻

工位屏网速不一样。如果各下各的、下完各自翻，快的 3 秒翻、慢的 40 秒翻，
中间这半分钟里前道已按新型号作业、后道还看着旧型号 —— **直接混批**。

所以切换分成两段：

```
① 班长点"切换到 X400"
   └─ 服务器 phase=prepare，广播目标型号（此时画面不动，继续播旧内容）
   └─ 各终端后台下载并校验本工序内容，顶栏显示"准备中 3/11"
   └─ 下完 → POST /api/ready 举手
② 所有在线终端都举手
   └─ 服务器 phase=activate，seq+1
   └─ 各终端同一瞬间整屏翻，翻完立即释放旧内容
```

**铁律：要么整批全翻，要么一台都不翻。** 不存在"一屏里混两个型号"的中间态。

### 5 分钟到点也翻

一台屏网络烂不能拖整个产线停产，所以超时（默认 5 分钟）**强制激活**：
备好的翻，没备好的保持旧画面并顶栏红字 `内容未就绪 · 请勿作业`，
管理端能指出是哪道工序没跟上（验收项 A10）。

### 本地只留一套，旧内容切完即删

终端磁盘上任何时候只有**当前这一套**（约 27MB），翻页成功后旧内容立即释放。
不做历史型号归档、不做"回滚到上一型号"的本地快照。好处是终端永远不会拿错型号播。

### 为什么不用 WebSocket

长轮询在原生 `http` 上就能写，零依赖。25 秒挂起 ≈ 一次普通请求，无线抖动时重连成本极低；
断线后 30 秒兜底轮询，网络恢复自动接上，不需要任何重连状态机。

## 三、快速开始

要求 **Node.js ≥ 22.5**（用内置 `node:sqlite`，**零 npm 依赖**，不用 `npm install`）。

```bash
node server.js                  # 默认 8092 端口
node server.js --port=8092      # 指定端口
```

首次启动自动建库并写入种子数据：**10 个机种（X200–X290）**，每个机种自动铺
**5 道工序（OP1 装配 / OP2 调试 / OP3 检验 / OP4 包装 / OP5 入库）**，内容全空。数据落在 `data/`（已 gitignore，含 `vwi.db` 与媒体文件）。

启动后控制台会打印局域网地址，终端装机时直接填：

```
  管理端    http://127.0.0.1:8092/
  终端画面  http://127.0.0.1:8092/player.html?op=OP30
  局域网访问（终端装机器上填这个）：
    http://192.168.1.4:8092
```

### 管理端六页

| 页面 | 干什么 |
|---|---|
| **作业内容**（总览） | 三段：产线概览（运行/停用/维修/保养各几条）→ 运行产线一行一条：`+ 指定正在生产的机种`（或当前机种 + `改`）→ `+ 排产下一个机种` → `换型` → 操作说明 |
| 线体设置 | 一张表：名称 / 工位数 / 可生产机种 / 状态 / 在线 / 操作。状态四个按钮（运行·停线·维修·保养）就地切；「可生产机种」自动统计 |
| 机种设置 | **定义层**：上面机种胶囊（编号 / 产品名称 / 可生产线体 / 已配几道），下面该机种的工序表（工序码 / 名称 / 做什么 / 播放方式 / 内容）。新建机种弹窗一次定「机种编号 + 产品名称 + 几道工序 + 使用线体」 |
| 媒体库 | **内容层**：先选机种 → 左边工序索引 → 右边上传图片 / PDF / 视频；勾允许类型、播放方式、排序、停留秒数 |
| 文件查询 | 全库文件：搜索、只看图片/视频/PDF、规格体检、清理未引用 |
| 终端监控 / 系统 | 看各屏状态；版本、服务地址、数据目录、托盘与自启（桌面程序才有） |

> 「作业内容」是**总览**，其余各功能项都是**设置**页——这条分工是有意的：
> 日常只开总览，配置改在设置里，避免误改。

### 工作台上的屏（终端 exe）

浏览器页只用于调试。**真正装在工位屏上的是 `terminal/` 里的接收端程序**：
kiosk 全屏、开机自启、看门狗、内容存在本机 —— 断网继续播，断电重启自己回来。

```bash
cd terminal
npm install        # 首次装 Electron 31（约 260MB）
npm start          # kiosk 全屏；npm run dev 为调试模式
```

装机是 `server`（服务器地址）+ `line`（哪条线体，可留空跟随服务端当前启用线体）+ `op`（哪道工序），
写在 `config.json` 里放 exe 旁边。
另有一个必读点：**维护退出键是 `Ctrl+Alt+Shift+Q`**，kiosk 下任务栏可能被盖住、托盘点不到。

完整说明见 [`terminal/README.md`](terminal/README.md)。

### 服务端（桌面程序，双击即用）

**现场用这个**：`server-gui/dist/ESOP-Server.exe`（v1.9.0），单文件免安装。
双击它就同时干两件事：把 HTTP 服务跑起来、把管理界面开成一个独立窗口——**全程不用浏览器、不用装 Node**。

| 场景 | 做法 |
|---|---|
| 日常使用 | 双击 exe，等窗口出来即可 |
| 关窗口 | **服务不会停**，缩到右下角托盘继续为 5 台终端服务；双击托盘图标能重新打开 |
| 真退出 | 右键托盘图标 →「退出服务端」（有终端在线时会二次确认） |
| 开机自启 | 系统面板里打开开关，或托盘菜单勾选 |
| 终端装机地址 | 系统面板里直接列出局域网地址并可复制，不用去翻 ipconfig |

界面顶栏的「系统」按钮里能看到：版本、服务端口、终端要填的服务端地址、数据目录、日志文件。
数据在 exe 同级的 `data\`，备份就备份它；日志在 `data\server.log`，出问题先看它。

<details>
<summary>源码方式运行</summary>

```bash
npm start            # 等价于 node server.js，监听 8092
npm run gui          # 以桌面程序方式启动（开发调试）
npm run gui:dist     # 打包 portable exe
```

打包环境两个坑（本机内网必需）：

1. **必须走公司代理**：`export https_proxy=http://sha1.sme.zscaler.net:443`。
   不设会报 `unable to get local issuer certificate`。
2. `build.electronDownload.isVerifyChecksum = false` 是**故意开着**的。
   `@electron/get` 每次打包都要联网拉 `SHASUMS256.txt` 校验 electron 的 zip，
   而这个校验文件**不走本地缓存**，代理经常在建连阶段就断（
   `Client network socket disconnected before secure TLS connection was established`），
   表现为每次打包都卡在 `packaging ... win-unpacked` 之后失败。
   electron 的 zip 本身是从 `%LOCALAPPDATA%\electron\Cache` 读的（命中缓存打印 `using cached artifact`），
   跳过的是它的哈希校验。**换机器或首次装依赖后要联网跑一次成功打包**，
   让 zip 进缓存，之后就能离线出包。

</details>

### 日常操作

1. **建机种**：机种设置 → 「+ 新建机种」→ **机种编号**（已预填一个没被占用的号，不想改就用它）、
   **产品名称**、几道工序、**使用线体**（点「+ 添加线体」一条条加，胶囊上的 ✕ 摘掉）→
   建好就铺出 `OP1…OPn`（名称默认装配/调试/检验），在下面的工序表里逐道改名称和「做什么」
2. **配内容**：媒体库 → 选机种 → 左「工序索引」点一道工序（或按「下一个」顺序过）
   → 勾「允许类型」→ 拖入图片 / 视频 / PDF → 选播放方式、排序、设停留秒数 → 保存
3. **指定 + 排产 + 换型**：作业内容 → 「运行产线」那一行里有三个动作：
   - **+ 指定正在生产的机种**：这一行还显示「未指定」时用它 —— 上线第一天屏还没装、
     或现场已经换过料而管理端停在老机种。直接落库、不等屏下载完（已有当前机种时按钮变成「改」）
   - **+ 排产下一个机种**：提前把下一炉排好，只记一笔、不动终端，可以提前一天排；点 ✕ 取消
   - **换型**：真要换时点它（排产之后才可点），按钮变亮显示「换型中 已就绪 2/5」→
     等各屏举手 → 全线同时翻
4. **加工序**：机种设置 → 工序表「+ 加工序」，一次要加十几道就用「批量加工序」（一行 `OP30 压装`）
5. **换线做同一机种**：机种设置 → 「改编号/名称」→ 「+ 添加线体」加一条即可 —— 内容不动，两条线共用一套
6. **整表维护**：工序表「导出」拿全厂一张表（`机种 / 工序码 / 名称 / 做什么`）→ 在 Excel 里改 →
   「导入」整份传回去；不知道什么格式点「模板」下一个

## 四、接口

```
GET    /api/board                 总览：全部线体（含 status 与 nextModelCode）+ 每线客户端状态 + overview 统计
POST   /api/board/switch          总览页换型，回 {ok, activated, phase}
POST   /api/board/current         直接指定「正在生产」的机种 {lineId, modelCode}（不走换型协议，seq +1）
POST   /api/board/next            排产下一个机种 {lineId, modelCode}；modelCode 传空 = 取消排产

GET    /api/models                 机种列表（done/total = 已配工序数 / 工序数，lines = 可生产线体）
POST   /api/models                新增机种 {code, name, processCount, lineIds[]}（一次把工序铺好）
PUT    /api/models/:id            改机种（编码 / 名称 / 可生产线体 lineIds[] 整批覆盖）

GET    /api/processes?modelId=    某机种的工序（含允许类型、播放方式、内容清单）
POST   /api/processes             加一道工序（{modelId, code, name?}）
PUT    /api/processes/:id         保存（name/note/maxMb/playMode/reqs/items，只传哪块改哪块，其余不动）
DELETE /api/processes/:id         删工序（连它的内容一起）

POST   /api/import/parse          解析 xlsx / csv，只回预览与逐行判定，不落库
POST   /api/processes/import      按确认过的行批量建/更新工序（mode: merge|update|update-only）
POST   /api/processes/import/undo 撤销某批次新建的工序（只删本批新建，不回滚改名）
GET    /api/export/processes.xlsx 导出工序清单：全厂一张表，四列（机种 / 工序码 / 名称 / 做什么）
                                  与导入模板逐列同构，改完能整份导回；?modelId= 可只导一个机种
GET    /api/export/template.xlsx  导入模板：标题行 + 两行示例，第二页是填写说明

GET    /api/lines                 线体列表（含 slots / status / modelCount / modelCodes）
POST   /api/lines                 新建线体 {name, slots, status}，编码自动生成 L1 / L2…
PUT    /api/lines/:id             改线体 / 改状态（status: running|stopped|maintain|care；
                                  老写法 {enabled:true} 仍然收，等价于 status=running）
DELETE /api/lines/:id             删线体：只断「可生产」的关系，**机种和内容一道工序都不丢**

GET    /api/playlist?modelId=&processId=    兼容接口：按工序取内容（老调用方传 stationId 也认）
PUT    /api/playlist              兼容接口：整批覆盖保存
GET    /api/playlist/all          全机种内容一览


POST   /api/media/upload?filename=           原始流上传，自动 sha256 去重
GET    /api/media                 媒体列表（含被引用次数）
POST   /api/media/gc              回收未引用媒体（默认 dryRun）
GET    /api/media/advice          规格体检（非 5:4、图片过大）

POST   /api/switch                {modelCode} 发起换型
POST   /api/switch/cancel         放弃本次换型（画面保持原机种）
POST   /api/ready                 {line,op,modelId} 终端举手：本工序已备齐
GET    /api/state?line=&op=&since=  长轮询（25 秒），返回 phase/seq/current/pending/online/ready

GET    /display/boot?line=&op=       终端启动自检：我是谁、现在该播什么
GET    /display/playlist?line=&op=&model=  终端拉清单（当前槽刷新与预备下载共用）
GET    /m/:id                     媒体流，支持 Range（视频拖动、断点续传）
```

**终端接口契约没变**：`/display/boot` 与 `/display/playlist` 仍按 `?line=&op=` 取，
服务端内部按「这条线的当前机种 + 工序码」找内容，多回了 `stationCode` / `stationName` /
`playMode` / `noStation` 四个描述字段（前两个是老名字，值就是工序码与工序名）。

工序码在本机种里不存在时**不再回 404**，而是 200 + `noStation` + 一句提示 —— 404 在终端上
表现为"连不上服务器"，现场会跑去查网络。

**现场 5 台终端不用改配置、不用升终端。**

**一期无鉴权**（用户明确「先不考虑权限管理」）。`op` 不是权限，而是"我是哪道工序"这个身份。
代价是内网任何人都能拉到内容，所以有一条硬约束：**服务端只能跑在车间内网，不得映射到公网。**

## 五、数据表（9 张）

| 表 | 作用 |
|---|---|
| `line` | 线体：编码（终端寻址用）、名称、`status` 四态、`slots` 工位数（只做展示） |
| `model_line` | 机种 × 线体（多对多）：这个机种能在哪几条线上做，`可生产机种` 就是它的反查 |
| `line_state` | 每条线的换型状态：当前机种、seq、pending、next（排产）、deadline |
| `model` | 机种（产品） |
| `process` | 工序：挂机种，`UNIQUE(model_id, code)`，带 `play_mode` 与 `import_batch` |
| `process_req` | 工序允许的文件类型、最小数量与最小分辨率 |
| `item` | 播放清单项：`(model_id, process_id)` 下的一条，带排序、停留时长、适应方式、缩放 |
| `media` | 媒体，sha256 内容寻址，多机种共用同一张图只存一份 |
| `setting` | 全局 KV：`rev` 等 |

**4.0.0 后 `station` / `station_req` 是空表**：建表语句还在 `SCHEMA` 里，那是为了让老库的
迁移路径只有一条（1.x → 2.x → 3.x → 4.0 一路走通），业务代码不再读写它们，迁移那一步会清空。

**刻意不建**：`user` / `session`（不做权限）、`release`（不做版本治理）、
`play_log`（不做统计报表）、`page` / `block`（不做版式）、`switch_log`（切换写进程日志即可）。

两个计数器分工要分清：
- `seq` —— 业务语义，**只在激活时 +1**，终端据此判断"该翻页了"（按线体各一份）
- `rev` —— 通信语义，任何需要通知终端的变化都 +1（进 prepare、激活、清单被改），**全局单调**

## 七、测试

```bash
node test/run.mjs                 # 服务端：195 项协议断言（临时实例，跑完焚毁）
cd terminal && node test/sync-test.cjs   # 终端：19 项数据层断言（连真实服务器）
```

服务端测试会起一个**临时数据目录**的实例（默认端口 8093），跑完自动关掉并删除数据——不会弄乱开发数据。

覆盖 195 项断言，重点在切换协议、工序模型与导入：

| 组 | 验的是什么 |
|---|---|
| 档案 | 10 机种 × 5 道工序，完成度分母 50（全厂一套） |
| 新建机种 | 一次定「机种编号 + 产品名称 + 几道工序 + 使用线体」；默认 OP1..OPn、默认名 装配/调试/检验 |
| **机种编号** | `/api/models` 带 `nextCode` 供弹窗预填；不传编号自动给 `M1`、`M2` 且不重复；产品名留空先用编号；删掉后号不占 |
| **直接指定当前机种** | `POST /api/board/current` 不等待举手即生效、seq 只 +1；指定成同一个不算换；排产撞上则清空；换型中不许改 |
| 可生产线体 | 多选即刻生效；一条线能挂多个机种，线体页的 `modelCount` 自动统计 |
| 上传清单 | 同文件去重、宽高解析、重复项拒绝、**失败保存不破坏原清单** |
| 无终端在线 | 直接激活（否则管理端永远卡在"准备中"） |
| 两段式 | prepare 不动 seq、1/2 台备好**不激活**、集齐才翻、seq 只 +1 |
| 工序隔离 | 不同工序内容互不影响、空内容显式返回 `empty` |
| **工序归机种** | 两道工序的机种两条线共用一套内容；改一道只改一处 |
| **类型闸门** | 没勾视频 → 放视频 `400`；勾上后放行 |
| **播放方式** | 只改 `playMode` 不动内容；改完 `/display/playlist` 立刻带新值 |
| **未配的工序码** | `?op=OP99` 回 200 + `noStation` + 提示，不是 404 |
| 换型投票 | 只统计目标机种真有的工序码，错配的屏不会把换型卡在 prepare |
| 导入 | 表头映射（认名不认列）、flat/single 两模式、merge/update/update-only、撤销本批 |
| 过期举手 | 拿旧机种举手返回 409 |
| 放弃切换 | 回到 idle、当前机种不变、不消耗 seq |
| 工序增删 | 删工序连内容一起删；同机种工序码唯一；删线体**不动**机种与内容 |
| **总览接口** | 一次返回全部线体、每道工序都占一个客户端位、带 `status` 与 `hasContent` |
| 媒体流 | MIME、Range 206、404 |

终端那 19 项测的是真机上最容易翻车的几件事（不需要 Electron，用假渲染层 + 真实文件操作）：

| 组 | 验的是什么 |
|---|---|
| 首次装载 | 内容真的落盘、文件数 = 清单条数、无 `.part` 残留 |
| 切换（A8） | 旧机种独有文件被删、磁盘只剩当前一套 |
| 断电重启（A5） | 不连服务器也能在 110ms 内出画面 |
| 断网（A3/A4） | 画面照样播，状态转离线，不抛错 |
| 连切三次 | 文件数与占用不增长 |

另外 `terminal/test/preview.html?s=1..7` 用假数据源驱动真正的播放器代码，
可逐个核对七种画面状态（需要 `node test/serve.cjs` 起预览服务）。
