# 在线VWI终端（接收端）

工作台上那台屏跑的就是它。职责只有一件：**把服务器上「当前型号 × 本工序」的作业指导书循环放出来**，
并且在服务器换型时整屏切过去。

它不联网也能播——内容提前存在本机，网络断了只影响"下一次换型能不能下载"。

---

## 一、装机（3 步）

1. 把 `ESOP-Client.exe` 拷到终端机任意目录（建议 `C:\VWI\`）。
2. 同目录放一个 `config.json`：

   ```json
   {
     "server": "http://192.168.1.100:8092",
     "line": "L1",
     "op": "OP30",
     "kiosk": true,
     "autoStart": true
   }
   ```

   | 字段 | 说明 |
   |---|---|
   | `server` | 服务器地址，带端口 |
   | `line` | **这台屏属于哪条线体**：填**线体编码**（`L1` / `L2` / `L08` / `WM` / `XB`），不是"一线"。留空 = 跟随服务端当前启用的线体 |
   | `op` | **这台屏是哪道工序**：填**工序码**（`OP10` / `OP30`）。填错会显示别的工序的指导书 |
   | `kiosk` | `true` = 全屏无边框置顶；调试时改 `false` |
   | `autoStart` | `true` = 开机自启 |

3. 双击 exe。第一次启动会在 `%LOCALAPPDATA%\esop-client\` 建工作目录并开始下载内容。

> 没有 `config.json` 也不会黑屏——会弹装机向导：填服务器 → 点「检测」 → 选线体 → 选工序 → 保存。
> 保存后会向服务端自报一次，页面上直接显示结果（已收到 / 待确认 / 已被指派到别处 / 这道工序已被占用）。

**为什么配置文件要放在 exe 旁边**：5 台机器装完，运维只要改这一份 JSON 再重启，不用进程序里点。

> ⚠️ **1.8.0 起有一条例外**：一旦管理端在工序页给这台屏指派过，本机 `%LOCALAPPDATA%` 里那份配置会
> 带上 `"managed": true`，**重启时它优先于 exe 旁的 json**。否则运维那份 json 会在下次重启时把管理端
> 改的号顶回去，屏又播错内容、再等几秒被纠正 —— 现场看到的就是"改了又变回去"。
> 想让 json 重新说了算：删掉本机配置里的 `managed` 字段（或整份删掉，重新装机）。

## 二、屏上看到的状态

正常播放时顶栏只显示 `型号 · 工序`，右侧一个绿点。异常时变化如下，**这些颜色就是现场唯一的诊断信息**：

| 顶栏 | 含义 | 现场该怎么办 |
|---|---|---|
| 🟢 在线 | 正常 | 无 |
| 🟠 准备中 3/11 | 服务器已下令换型，正在下载新内容。**画面仍是旧内容**，下载完才整屏翻 | 等，不要动 |
| 🔴 内容未就绪 · 请勿作业 | 这台没跟上换型，屏上还是旧型号内容（红底闪烁） | **停止作业**，等它自己补完 |
| 🟠 内容不全 | 该型号本工序内容不全 | 通知工程部补内容 |
| ⚪ 离线 | 连不上服务器，**画面照常播** | 一般不用管，网络恢复自动接上 |
| 中央提示页 | 本机没内容（首次装机 / 该工序还没配） | 等，配置好后自动开始播 |

## 三、管理端指派（1.8.0）

以前"这台屏该放哪道工序"只能在屏上设，设错了服务端看不出来。现在反过来：
**屏把自己填的线号 + 工序号报上去，管理端在工序页指一下，指错了服务端改、屏跟着改。**

| 环节 | 发生什么 |
|---|---|
| 保存设置 | 立刻 `POST /api/clients/hello` 报一次，设置页底部直接写出结果（不用回管理端按 IP 反查） |
| 管理端指派 | 长轮询 `/api/state` 里多出 `assign: {line, op, src}`，终端发现与本地不同就改写 `config.json`、重启同步 |
| 屏上提示 | 画面顶部挂 4 秒「配置已由管理端更新为 L1 / OP30」—— 内容自己换了，工人得知道是管理端干的 |
| 没被指派 | 完全按屏上自己填的号播，`assign` 字段不出现（新屏装完到指派之间不会黑屏） |

**播放归属**：没指派 → 按自报；指派了 → 按指派（不论屏上报的是什么）。所以"屏上填错"不再是死结，
管理端改一下就行；反过来，在屏上手工改号也会在几秒内被管理端改回来 —— 要调岗请在管理端改。

## 四、维护操作

| 想做什么 | 怎么做 |
|---|---|
| 换工序 / 换服务器 | 改 exe 旁的 `config.json`，重启程序 |
| 打开内容目录 | 托盘图标右键 → 打开内容目录（`%LOCALAPPDATA%\esop-client\content\current`） |
| 看日志 | 托盘右键 → 打开日志，或直接看 `%LOCALAPPDATA%\esop-client\logs\terminal.log` |
| 强制重新下载 | 托盘右键 → 重新同步内容 |
| **退出程序** | 托盘右键 → 退出，或按 **Ctrl+Alt+Shift+Q** |
| 界面卡死不刷新 | 程序自带看门狗：连续 3 次（约 30 秒）收不到页面心跳会自动重载 |

程序**不允许**被 Alt+F4、F11、Ctrl+W 关掉——这是刻意的，车间的屏不该能被人随手退出。

## 五、本机存了什么

```
%LOCALAPPDATA%\esop-client\
  config.json          装机向导写出来的那份（exe 旁的会覆盖它）
  content\
    index.json         当前这套内容的索引（型号 + 文件清单）
    current\           正在播的那一套，文件名是 <内容哈希>.<扩展名>
  logs\terminal.log
```

- 稳态下 `current\` 里**只有当前这一套**（约 27MB）。比这大一倍就说明有旧文件没删干净。
- 换型时新内容先下到 `current\`（文件名不同，不会覆盖旧的），校验通过、画面翻过去之后才删旧文件。
  所以**切换失败、断电、断网都不会毁掉正在播的内容**。
- 删除失败（Windows 上视频文件被播放器占住是常事）会进入重试队列：60 秒后再试、下次启动再试。

## 六、验收怎么测

| 编号 | 怎么测 | 通过标准 |
|---|---|---|
| A2 | 服务器上点换型，用手机录屏 | 全程不黑屏、不闪白、不回桌面 |
| A3 | 拔掉 AP | 画面继续播，顶栏转"离线" |
| A4 | 断网放一夜 | 第二天画面还在播 |
| A5 | 直接拔电源再上电 | 自动全屏回到当前型号，不需要人操作 |
| A10 | 关掉某台的 WiFi 后换型 | 5 分钟到点其它屏照常翻，这台亮红字 `内容未就绪 · 请勿作业` |

## 七、开发与测试

```bash
npm install          # 装 Electron 31（首次）
npm run dev          # 开发模式：非 kiosk、可开 DevTools
npm start            # 生产模式：kiosk 全屏置顶

node test/assign-test.cjs    # 指派下发与自报：35 项（自带假服务器，不连网）
node test/sync-test.cjs      # 数据层集成测试（不需要 Electron，连真实服务器跑）
node test/migrate-test.cjs   # 配置目录迁移：18 项（老目录不许把屏变成"未装机"）
node test/serve.cjs          # 起预览页 http://127.0.0.1:8099/test/preview.html?s=1
npm run dist                 # 打 portable exe（需先装 electron-builder）
```

`test/sync-test.cjs` 覆盖的是真机上最容易翻车的几件事：内容是否真的落盘、sha 是否校验过、
切换后旧文件是否删掉、断网/重启能否不看网络就出画面、连切三次磁盘是否增长。
它跑在临时目录里，不会碰真机数据。

`test/preview.html` 用假数据源驱动真正的播放器代码，`?s=1..7` 分别对应正常播放、自动翻页、
整屏切换、掉队告警、空内容、准备中、离线七种状态，用来核对画面。
